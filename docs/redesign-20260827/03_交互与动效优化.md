# 智愈寻真 · 交互与动效优化方案

> 文档编号：03 · 版本：v1.0 · 日期：2026-08-27
> 适用范围：移动端（Flutter，`mobile/`）+ 后端分页契约（`backend/`）
> 关联：《整体重设计方案》系列文档之一

---

## 1. 现状分析

用户反馈核心痛点：
1. **列表未分页加载，一次性渲染全部数据** → 首屏卡顿、滚动掉帧；
2. **操作反馈不够跟手，缺微交互细节** → 按压无反馈、加载态生硬、转场僵硬。

### 1.1 逐页核实（引用真实文件）

| 页面 | 文件 | 现状 | 是否分页 | 加载反馈 |
|---|---|---|---|---|
| 病例广场 | `mobile/lib/features/teacher/market/case_market_screen.dart` | `_loadCases()` 单次调用 `TeacherService().getMarketList()`（无分页入参，走后端默认 **pageSize=50**），一次塞入 `_cases`；`_filtered` 在**内存里对全量列表做过滤/搜索**；渲染用 `ListView` + `list.map().toList()` **一次性构建全部子节点** | ❌ 一次性 | 全屏 `CircularProgressIndicator` |
| 作业创建（引用面板） | `mobile/lib/features/teacher/assignments/assignment_create_screen.dart:720` | 同样单次 `getMarketList()`，默认 50 条全量 | ❌ 一次性 | 局部 loading |
| 浏览题库 | `mobile/lib/features/student/training/question_bank_screen.dart` | 已是服务端分页（`_pageNum/_pageSize=10`，`getQuestions(pageNum,pageSize)`，读 `list`+`total`），但用**传统上一页/下一页分页控件**，每翻页整屏 spinner | ✅ 有（传统分页器） | 整屏 spinner，翻页跳动 |
| 错题本 | `mobile/lib/features/student/mistakes/mistakes_screen.dart` | `_loadMistakes()` 调 `getMistakes()` **不传分页参数**，只读 `records`（即**只有第一页 10 条**）；嵌入一个大 `ListView`，`list.map(_buildMistakeCard)` 内联渲染；`_filtered` 只对已加载的 10 条过滤 | ⚠️ 只取首屏，无翻页能力 | 整屏 spinner |
| 学习档案 | `mobile/lib/features/student/archive/learning_archive_screen.dart` | 聚合 stats/goal/overview/weakness，weakness 仅 `take(5)`，非大数据列表 | — 非分页场景 | 整屏 spinner |

**结论**：真正需要分页重写的重点是「病例广场」与「错题本」；「浏览题库」已分页但停留在传统分页器体验；「学习档案」是仪表盘，保持首屏即时加载即可，但应加骨架屏。

### 1.2 现有微交互资产（可复用）

- **柔和页面转场**已就绪：`app_theme.dart:467 _SoftPageTransitionsBuilder`，全局统一「淡入 + 轻上移」240ms / easeOutCubic。这是好基础，问题在于**通用于所有 push，无平台差异（iOS 右滑返回 / Android predictive back 缺失）**。
- **按压缩放**已就绪：`app_widgets.dart:16 PressableScale`（0.97 按压 + elasticOut 回弹），但**未全局覆盖**——`case_market`、`mistakes` 的筛选 chip、卡片等大量可点元素直接裸用 `GestureDetector`/`Container`，无按压反馈。
- **底部导航动效**已就绪（`bottom_tab_bar.dart` 胶囊 + 颜色/缩放过渡），无需改动。

## 2. 全局微交互设计

### 2.1 按钮按压态

沿用并**推广** `PressableScale`，同时统一水波纹（InkWell splash）节奏。

#### 现状问题
- 大量 `GestureDetector`（筛选 chip、卡片、工具宫格）裸触发，按压时**无任何视觉反馈**，跟手度差。
- 自定义按钮（`AppPrimaryButton` 等）用 `PressableScale` + `ElevatedButton`，已具备缩放反馈，但部分 `AppGhostButton`（dashed）未加水波纹。

#### 方案
- **统一组件**：所有可点击元素默认用 `PressableScale`（缩放）+ 底层 `Material/InkWell`（splash/ripple 水波纹），二者叠加。
- **按压参数**：按下缩放 0.97、90~100ms（easeOut）；回弹 elasticOut 180ms（见 §4 参数表）。
- **全局兜底**：在 `ThemeData` 的 `splashColor` / `highlightColor` 统一收敛为「主色 8% 透明度」，避免 ripple 突兀。

#### 关键实现（封装 `AppPressable`）
```dart
class AppPressable extends StatefulWidget {
  final Widget child;
  final VoidCallback? onTap;
  final Color? splashColor;   // 默认 primary.withValues(alpha: .08)
  final BorderRadius? borderRadius;
  const AppPressable({super.key, required this.child, this.onTap,
      this.splashColor, this.borderRadius});
  @override
  State<AppPressable> createState() => _AppPressableState();
}
class _AppPressableState extends State<AppPressable> {
  bool _pressed = false;
  @override
  Widget build(BuildContext context) {
    return Listener(  // 主动画：按压缩放
      onPointerDown: _pressed == false ? (_) => setState(() => _pressed = true) : null,
      onPointerUp:   _pressed == true  ? (_) => setState(() => _pressed = false) : null,
      onPointerCancel: _pressed == true ? (_) => setState(() => _pressed = false) : null,
      child: AnimatedScale(
        scale: _pressed ? 0.97 : 1.0,
        duration: _pressed ? const Duration(milliseconds: 100)
                           : const Duration(milliseconds: 180),
        curve: _pressed ? Curves.easeOut : Curves.elasticOut,
        child: Material(        // 被动画：水波纹
          color: Colors.transparent,
          borderRadius: widget.borderRadius,
          clipBehavior: Clip.antiAlias,
          child: InkWell(
            onTap: widget.onTap,
            splashColor: widget.splashColor ??
                AppColors.primaryOf(context).withValues(alpha: .08),
            borderRadius: widget.borderRadius,
            behavior: HitTestBehavior.opaque,
            child: widget.child,
          ),
        ),
      ),
    );
  }
}
```

### 2.2 列表滑动阻尼 / 回弹

Flutter 原生 `ScrollConfiguration` 默认 physics 已提供 iOS/Android 惯性 + 回弹。建议：

- **全局统一回弹（overscroll）**：在各 `ListView/GridView` 声明 `physics: const BouncingScrollPhysics(parent: AlwaysScrollableScrollPhysics())`，iOS/Android 一致体验；`RefreshIndicator` 已存在，配合 `BouncingScrollPhysics` 回弹更自然。
- **不重造物理**：`BouncingScrollPhysics` 底层即 `SpringDescription`（质量/刚度/阻尼），符合"转场物理曲线自然"。如需自定义，可 `SpringDescription.withDampingRatio(..., ratio: 0.75)` 传给 `Simulation`，此处不做定制，用框架默认即可，控制点在于**避免在 `build` 里 `setState` 全量重渲染**（§3 的虚拟列表解决）。
- **加载兜底分页**：滚动到底加载更多时，`ScrollController.position.extentAfter < 300` 触发（见 §3）。

### 2.3 页面转场：右滑返回 + Predictive Back

现有 `_SoftPageTransitionsBuilder`（淡入+轻上移）**通用于 push/pop**，但存在两个体验缺口：

| 平台 | 缺口 | 方案 |
|---|---|---|
| iOS | 无「右滑返回」手势（`CupertinoPageTransition` 才自带） | iOS 平台改用 `CupertinoPageTransitionsBuilder`，获得原生**边缘右滑返回**；其余交互仍保留柔和淡入，二者并行（iOS 用 iOS 原生向右滑动，Android 用柔和淡入，或统一柔和 + 开启 back gesture） |
| Android | 无 Predictive Back 预测式返回动画 | Material 3 启用 `AndroidPredictiveBackPageTransitionsBuilder`（Flutter 3.22+），返回时可预览上一页 |

**推荐**：
```dart
pageTransitionsTheme: const PageTransitionsTheme(builders: {
  // iOS：原生右滑返回（跟手）+ 淡入
  TargetPlatform.iOS: _SoftSlideBackTransitionsBuilder(),   // 见下
  // Android：预测式返回 + 柔和淡入
  TargetPlatform.android: _SoftPredictiveBackBuilder(),
  // 桌面统一柔和淡入
  TargetPlatform.macOS: _SoftPageTransitionsBuilder(),
  // ...
})
```
> 说明：`_SoftPageTransitionsBuilder` 保留用于 push（自下而上轻滑）；pop 方向由 iOS `CupertinoPageRoute` 自带的 `backGestureWidth` / 右滑驱动，Android 由预测式返回动画接管，达成"按返回"跟手不僵硬。具体封装的 `_SoftSlideBackTransitionsBuilder._SoftPredictiveBackBuilder` 放在 `app_theme.dart` 内实现（可叠加现有淡入，或直接委托给系统 ISO builder + 保留淡入缓释）。

### 2.4 加载骨架屏（Shimmer）

现状全部用 `Center(CircularProgressIndicator)`，白屏/转圈观感差。方案：**进入页面首屏用「骨架屏 + shimmer」，刷新/加载更多用「局部指示器」**。

- 骨架屏形态与真实卡片一致：封面块 + 标题双行条 + 元信息条 + 按钮占位。
- shimmer 用 Lighthouse 柔和高光：`AnimatedBuilder` + `LinearGradient`，2 个周期秒。

#### 骨架屏 Widget 关键实现
```dart
class AppSkeleton extends StatefulWidget {
  final double? width; final double? height;
  final BorderRadius borderRadius;
  const AppSkeleton({super.key, this.width, this.height,
      this.borderRadius = const BorderRadius.all(Radius.circular(8))});
  @override State<AppSkeleton> createState() => _AppSkeletonState();
}
class _AppSkeletonState extends State<AppSkeleton>
    with SingleTickerProviderStateMixin {
  late final AnimationController _c = AnimationController(
      vsync: this, duration: const Duration(milliseconds: 1400))..repeat();
  @override void dispose() { _c.dispose(); super.dispose(); }
  @override
  Widget build(BuildContext context) {
    return AnimatedBuilder(
      animation: _c,
      builder: (_, __) => ShaderMask(  // 高光从左扫到右再回来
        shaderCallback: (rect) => LinearGradient(
          colors: [AppColors.surfaceOf(context),
                   AppColors.paper2Of(context),
                   AppColors.surfaceOf(context)],
          stops: const [0.3, 0.5, 0.7],
          begin: Alignment(-1 + _c.value * 2, 0),  // 由 -1 → 1 扫描
          end:   Alignment( 1 + (_c.value * -2) , 0),
        ).createShader(rect),
        blendMode: BlendMode.srcATop,
        child: Container(width: widget.width, height: widget.height,
            decoration: BoxDecoration(
              color: AppColors.surfaceOf(context),
              borderRadius: widget.borderRadius,
            )),
      ),
    );
  }
}
```
> 依赖：无需新增第三方包，纯 `AnimatedBuilder` + `ShaderMask` 实现。骨架屏列表由「卡片骨架 × N 行」拼装，命中 `_isInitialLoading` 时替换整屏。

## 3. 列表分页方案选型

### 3.1 对比：传统分页器 vs 无限滚动 + 虚拟列表

| 维度 | 传统分页器（现有题库做法） | 无限滚动 + 虚拟列表（推荐） |
|---|---|---|
| 首屏 | 需用户点"下一页"才加载 | 首屏只渲染一屏（如 10~20） |
| 渲染成本 | 单页少，但翻页全屏刷新 | `ListView.builder` **惰性构建可见 Items**，隐藏的回收，天然虚拟化 |
| 跟手度 | 翻页跳转，体验割裂 | 滚动自然，加载更多附在尾部 |
| 后端依赖 | 已支持 `PageParam` | 同样只依赖 `PageParam`，契约不变 |
| 数据完整性 | 可跳页、跳过 | 需滚动才能看到更多（对无限流可接受） |
| 实现成本 | 已有雏形 | 需 `ScrollController` + 末尾触发，成本略高但收益大 |

**结论：推荐「无限滚动 + `ListView.builder` 虚拟列表 + 骨架屏」**。

理由：
1. `ListView.builder` 天生虚拟化，**只 build 可视区行**，直接解决"一次性渲染全部数据 → 首屏卡顿/掉帧"；
2. 用户反馈的"滚动掉帧"根因就是全量 Item 常驻树 + 复杂卡片重复 layout。改成 builder 后掉帧从根本上消除；
3. 后端已支持 `PageParam(pageNum,pageSize)` + `PageResult(list,total,page,pageSize)`，客户端 `pageNum` 递增即可，契约零改动；
4. 对医学题意浏览/错题复盘这类**顺序浏览**场景，无限滚动契合度高于翻页器。

### 3.2 Flutter 关键实现

#### A. 自实现的无限滚动 + ListView.builder（推荐，无新依赖）

```dart
// 分页状态（以病例广场为例改造 _CaseMarketScreenState）
final ScrollController _scroll = ScrollController();
final List<_CaseData> _items = [];
int _pageNum = 1;
static const int _pageSize = 15;
bool _hasMore = true;
bool _loadingMore = false;

@override
void initState() {
  super.initState();
  _loadFirstPage();
  _scroll.addListener(_onScroll);
}
void _onScroll() {
  if (_scroll.position.extentAfter < 300 && !_loadingMore && _hasMore) {
    _loadMore();
  }
}
Future<void> _loadFirstPage() async {
  _pageNum = 1; _items.clear(); _hasMore = true;
  await _loadMore();                       // 首次走骨架屏 loading
}
Future<void> _loadMore() async {
  if (_loadingMore || !_hasMore) return;
  setState(() => _loadingMore = true);
  final data = await StudentApi().getMistakes(   // 或 CaseMarketApi().getCaseList
    pageNum: _pageNum, pageSize: _pageSize);
  final records = (data?['records'] ?? data?['list'] as List?) ?? [];
  if (!mounted) return;
  setState(() {
    _items.addAll(records.map(...));       // 累积
    _hasMore = records.length >= _pageSize;  // 本页不足 size 视为到底
    _pageNum++;
    _loadingMore = false;
  });
}
// —— 渲染 ——
ListView.builder(
  controller: _scroll,
  padding: const EdgeInsets.only(top: 6, bottom: 100),
  physics: const BouncingScrollPhysics(parent: AlwaysScrollableScrollPhysics()),
  itemCount: _items.length + (_hasMore ? 1 : 0),   // +1 为尾部加载器
  itemBuilder: (context, i) {
    if (i >= _items.length) return _footerLoader(_loadingMore);  // 底部转圈
    return _caseCard(data: _items[i], ...);
  },
)
Widget _footerLoader(bool loading) => loading
    ? const Padding(padding: EdgeInsets.all(16),
        child: Center(child: SizedBox(width:22, height:22,
            child: CircularProgressIndicator(strokeWidth: 2.5))))
    : const SizedBox.shrink();
```
> 要点：`_hasMore` 以「返回条数 == pageSize」判断是否到底；顶部下拉刷新处重置 `_pageNum=1` 并清空后重新加载；尾部 loader 提供"加载更多"的持续反馈——解决"操作反馈不够跟手"。

#### B. 方案二（可选）：scroll_to_pagination 包
- 依赖需新增 `scroll_to_pagination`。适合不想自己写 `_onScroll` 的情况，但包体积/Jedis 版本需评估。
- 不引入也能用自实现方案 A 用半屏代码搞定，故**默认选 A**，不新增依赖（规避依赖风险与 pub 版本锁定问题）。

### 3.3 骨架屏列表（复用 §2.4 `AppSkeleton`）
```
itemCount: 5（一屏可见）
itemBuilder: _caseSkeleton()  // 封面块(高60) + 两行文字条 + 双按钮占位
```

### 3.4 后端需配合的契约（沿用现有）

- 请求：`PageParam`（`pageNum` 从 1 起、`pageSize`），已在 `backend/.../common/param/PageParam.java`。
- 响应：`PageResult`（`list`/`total`/`page`/`pageSize`），已在 `backend/.../common/result/PageResult.java`。
- **遗留问题（需统一）**：前端各页读取分页字段路径不一致——`case_market`/`mistakes` 读 `records`（并兼容 `cases`），题库读 `list`。落地时应**统一为 `list`**（`PageResult` 规范字段），或在 service 层做一次归一化映射，避免各页面 `??` 兜底链。

## 4. 动效时序参数表

> 所有时长遵循"快反馈（<100ms 感知）+ 自然曲线 + 克制调节"，兼顾医学教学应用的专业克制。

| 微交互 | 时长 | 曲线 | 目标 |
|---|---|---|---|
| 按钮按压（按下） | **90~100ms** | `easeOut` | 按压 <100ms 即时"跟手" |
| 按钮回弹（抬起） | 180ms | `elasticOut` | 轻快回弹不俗气 |
| 水波纹（InkWell splash） | 按系统（约 120~200ms） | 线性淡出 | 反馈不阻塞 |
| 页面 push 转场 | **240ms** | `easeOutCubic` | 柔和递进（沿用现有） |
| 页面 pop 反向 | 240ms | `easeInCubic` | 方向一致（沿用现有） |
| iOS 右滑返回 | 随手势速度（较快） | 原生 | 跟手可打断 |
| Predictive Back | 随系统（约 300ms） | 原生 | 可预览返回 |
| 底部 tab 滑块 | 360ms | `easeOutCubic` | 跟随平滑（现存） |
| tab 图标激活 | 320ms | `easeOutBack` | 轻微弹跳（现存） |
| 展开/折叠 | 180ms | `easeOut` | 列表 展开收拢 |
| 骨架屏 shimmer | 1400ms / 周期 | 线性往返 | 高频视觉占位 |
| 加载更多尾部 | 常驻转圈 | — | 持续反馈 |
| SnackBar 出现/消失 | 200ms | `easeOut` | toast 自然浮现 |

**响应性基准（可量化验收）**：
- 按钮操作反馈（按下即有视觉变化）≤ **100ms**；
- 滚动 60fps，掉帧率（jank）≤ 0.5%；
- 首屏可交互（TTFI）≤ 1.5s（见 §5）。

## 5. 预期效果对比 Before / After

| 指标 | Before | After | 说明 |
|---|---|---|---|
| 病例广场首屏渲染节点 | 50 个复杂卡片全量 build | 仅可视 ~6 个卡片（惰性 builder） | 首屏内存/布局骤降 |
| 首屏时间（TTFI） | 串行等 50 条 JSON 解析 + 全量 layout | 骨架屏即时展示 + 15 条首屏 | 感知从"白屏转圈"→"秒出" |
| 滚动掉帧（jank） | 全量 Item 常驻滚动有掉帧 | 虚拟化回收，基本无 jank | 60fps 稳定 |
| 跟手感（按压） | 多元素无反馈 | 全局 `AppPressable` 缩放+波纹 | 操作反馈即时 |
| 转场体验 | 单一淡入上移 | iOS 右滑返回 + Android 预测式返回 | 平台化、可打断 |
| 加载反馈 | 整屏 spinner | 骨架屏 + 尾部无限加载 | 持续可感知 |
| 错题本 | 只能看第一页 10 条 | 无限滚动可看全部 | 功能完整 |

**量化验收指标**（上线前用 profile+Performance Overlay 核对）：
- 按压反馈延迟 ≤ 100ms；
- 列表滚动刷新帧占空比（frame build interval）≤ 16ms（60fps）；
- 首屏骨架屏出现 ≤ 200ms，真实内容首帧 ≤ 1.5s。

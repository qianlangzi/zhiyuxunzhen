# 智愈寻真 · 信息架构重构方案

> 版本：v1.0 ｜ 日期：2026-08-27 ｜ 适用范围：学生端 / 教师端 Flutter 移动端
> 关联文档：《移动端信息架构重构方案 v2.md》（2026-08-22）——本文结论与该文档的取舍关系见 §5。

## 0. 结论摘要（TL;DR）

- 用户反馈的三个痛点（首页空荡、四个病例入口重叠、功能未收敛）**均已命中真实代码**，非设计失真。
- 直接**采纳《v2 方案》**（学生端 学习/训练/成长/我的，教师端 工作台/备课/°班级/我的），不做重写；本文只做**增量收敛**——把散落在练习页的四个病例入口合并为「一条主流程 + 两个快捷入口 + 一个总览页」。
- 收敛原则一句话：**病例实训为主流程、病例问诊为实训内的子步骤、每日一例为学习页快捷入口、病例库为全部病例总览页（Tab/筛选区分）**。
- 首页由「空荡」改为「有引导」：问候 → 搜索 → **今日目标卡（新增）** → 学习热力 → 学习任务主卡 → 宫格（每日一例 / 教材 / 刷题）。

## 1. 现状分析

### 1.1 四入口重叠：全部集中在「练习」Tab

学生端当前 4 Tab（`mobile/lib/shared/widgets/bottom_tab_bar.dart`，`studentTabs`）为 **学习 / 练习 / 成长 / 我的**。其中「练习」Tab 由
`mobile/lib/features/student/market/student_case_market_screen.dart` 承载，是**唯一的病例入口页**，而「病例实训 / 病例问诊 / 每日一例 / 病例库」四个入口全部挤在这一屏，功能重叠：

| 四个入口 | 所在区块 | 触发动作 | 存在问题 |
| --- | --- | --- | --- |
| **病例实训**（顶部渐变主卡） | `_buildHeroCard()`（L223） | 底部按钮「开始问诊」→ `_startGuide()` → 进入首个病例问诊室 | 主入口，语义最重，却与下方「病例问诊」重复 |
| **病例问诊**（宫格单元） | `_buildTrainGrid()`（L329，`_trainCell` title=「病例问诊」L337） | 点击 → 同样走 `_startGuide()` | **与「病例实训」完全同动作**，是纯重复入口 |
| **每日一例**（琥珀横幅） | `_buildDailyCaseEntry()`（L423） | 跳 `DailyCaseScreen` | 其锚点在「学习」含义下，却驻留在训练页 |
| **病例库**（底部列表） | `_buildSectionHeader('病例库')(L177)` + 科室筛选 + 列表 | 每个病例「开始问诊」 | 本质是「全部病例总览」，与顶部主卡语义层级被压平 |

**核心问题**：`_startGuide()` 被「病例实训」主卡和「病例问诊」宫格**两处调用**，做的是同一件事（进入首个病例问诊室）。用户在同一屏看到四个都在「做病例」的入口，却分不清谁是新流程、谁是快捷、谁是总览——决策成本高，且四种入口被压成同一层级。

### 1.2 首页空荡
`mobile/lib/features/student/home/student_home_screen.dart`（「学习中心」）当前布局为：问候 → 全局搜索 → **学习热力（大占屏但语义弱）** → 学习任务主卡 → MedicalDisclaimer。缺少「我该做什么 / 今天还剩什么」的引导组件，热力图仅展示数据统计，不产生任务感，首屏内容偏空、功能引导弱。

### 1.3 功能未收敛
四入口、学习热力、学习任务、通知等各组件散落 `home / market` 两页，彼此数据源重复拉取（首页与练习页都各自 `getReportOverview()`、`getTodayDailyCase()`），未形成「一条学习动线」，且页面目录按旧命名组织（`student/market/` 实为训练页）。

## 2. 新导航结构

### 2.1 总体原则（令牌级）

- 底部 Tab 恒 ≤ 4，语义锁定为**动词/时间轴**：**学（学习）→ 练（训练）→ 看进步（成长）→ 我的**。
- **一屏一个主目标**：每页「主卡 + 宫格 + 次级入口」三级，主卡承载该页第一目标。
- **每个病例动作只有一个心智位**：
  - 主流程 = **病例实训**（训练 Tab 渐变主卡）
  - 子步骤 = **问诊室（病例问诊）**，从主卡/病例列表进入，是实训内部的对话环节，**不设独立宫格**
  - 快捷入口 = **每日一例** → 学习 Tab 宫格卡片；训练 Tab 仅在顶部统计中带一句角标提示，不再独占横幅
  - 总览页 = **病例库** → 训练 Tab 底部「全部病例」列表，用科室/高评分筛选区分，兼作病例实训的选病例入口

### 2.5 首页引导组件（克制原则）

新增的「今日目标」卡遵循**克制**：不堆数据看板，只有一个进度环 + 至多 3 行可完成任务（每日一例 / 待办作业 / 系统推荐病例），点击直达对应动作。其余数据类（热力、统计）排在次席。**不新增第二张数据大卡**，避免再次变 "空荡→堆砌"。

## 4. 预期效果对比

| 维度 | Before（现状） | After（重构后） |
| --- | --- | --- |
| **病例入口数量** | 练习页同屏 4 个（病例实训 / 病例问诊 / 每日一例 / 病例库），其中 2 个动作完全相同 | 收敛为 **1 主流程（实训）+ 1 总览（病例库）**，每日一例迁学习页，问诊降为子步骤；同屏去重 |
| **用户决策成本** | 看到四个"做病例"入口，分不清主次，误点重复入口 | 一个主目标（实训主卡）显著，其余克制，路径唯一（实训→问诊室→OSCE） |
| **首页引导性** | 问候+搜索+热力+任务卡：只展示数据、无"该做什么"，首屏空荡 | 新增**今日目标卡**（进度环+3 项任务）+ 每日一例宫格：开屏即知今日任务，引导去"训练" |
| **功能收敛度** | 数据源在多页重复拉取，入口语义错位（market≈training） | 目录归位 `training/`，动线单一，心智位唯一 |

## 5. 与《移动端信息架构重构方案 v2》的关系

**结论：采纳 v2 + 增量调整，不改写，两份方案不冲突。**

- **v2 已满足绝大部分诉求**：其学生端 4 Tab＝学习/训练/成长/我的，教师端＝工作台/备课/°/我的，且 §2.2 的「训练」Tab 本身就定位为「病例实训主卡＋病例列表」——**v2 事实上已经给出了四个病例入口的收敛方向**（每日一例进学习宫格、病例库做训练总览）。
- **本文 = v2 的落地补齐**：在 v2 基础上，只做三处增量：
  1. 明确指出并**删除练习页中与「病例实训」重复的「病例问诊」宫格 cell**（v2 未细到 cell 级，本文落实）；
  2. 落地 v2 提出的**首页「今日目标」引导卡**（原方案只列了学习任务/热力，未给引导组件）；
  3. 教师端以**当前已落地的「班级」Tab** 为准（v2 文案为「病例广场」），明确二者为"命名微调、精神一致"。
- **后续维护约定**：以本文为收敛层、v2 为结构层，二者叠加使用；任何 tab 数/命名改动需同时更新两文档，避免漂移。

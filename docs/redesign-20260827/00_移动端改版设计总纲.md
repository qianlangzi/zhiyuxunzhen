## 2. 结论综述

四次专项均基于 `mobile/lib` 当前代码取证，确认用户反馈全部命中真实代码，**不是设计失真**：

- **入口重叠**：学生「练习」Tab 首页 `student_case_market_screen.dart` 同屏堆 4 个病例入口，其中「病例实训」渐变主卡（`_startGuide`）与「病例问诊」宫格 cell（`_trainCell` title=「病例问诊」）**走的是同一个 `_startGuide()`**，是纯重复。同时「每日一例」把学习含义的入口驻留在训练页、「病例库」被压成与主卡同级的列表。
- **首页空荡**：`student_home_screen.dart` 只有 问候→搜索→热力→任务卡，无"今天该做什么"的引导组件。
- **列表不分组**：病例广场一次拿后端默认 pageSize=50 全量、`_filtered` 内存过滤、`ListView` 一次性 build；错题本只读首屏 10 条且无翻页 UI。
- **"AI 味"**：主按钮 `AppRadius.full` 胶囊 + 满宽渐变主卡 + 双层阴影 + 装饰水印圆 + 排版清一色 w600，装饰密度过高。
- **硬编码/对比度**：检出 13 处 `Color(0x…)` 直写 + 40+ 处 `Colors.white/black87/grey`；深色 `text4` 仅 4.3:1 踩线；`essay_review_screen` 的 `Colors.black87` 落在深色朱砂软卡上对比度 <1.5:1 **不可读**。

**改造总体思路 = 减法 + 收敛 + 让令牌体系跑满**，不推倒重来：现有 `ThemePalette × lerp`、柔和转场、`AppColors.*Of` 取色体系是很好的地基，全部在其上做增量。

## 4. 落地顺序（三阶段建议）

### 阶段 A —— 止血（高优先，先解"卡顿 + 看不懂 + 深色刺眼"）
1. C-1 / C-2 / C-4：硬编码 → 令牌化，`essay_review` 黑字、`main.dart` 兜底页、深色 `text4` 对比度先修（C-3）。
2. I-1 / I-2 / I-4：病例广场、错题本、题库改无限滚动 + 骨架屏（解决"一次性渲染→卡顿"）。
3. IA-1 / IA-3：删重复「病例问诊」cell + 首页「今日目标卡」（解决"入口重叠、首页空荡"的第一观感）。
4. V-3：个人页 / 教师首页 hero 去渐变去装饰（最重的"AI 味"来源）。

### 阶段 B —— 视觉收敛（中优先，全部走"少即是多"）
- V-1 圆角重调、V-2 阴影单层化、V-4 排版层级、IA-2/IA-4/IA-5 训练/成长语义与目录归位。
- V-6 切换过渡、I-3 `AppPressable` 全局按压、I-5 iOS 右滑返回 + Android Predictive Back、I-6 回弹统一。
- C-5 / C-6 首屏惰性 + 图片缓存。

### 阶段 C —— 增强（可排期）
- V-5 高对比主题、V-7 三态 themeMode + iOS 跟随系统、C-7/C-8 语义加固、I-7 后端字段归一与过滤参数。

## 5. 关键风险与依赖

| 风险/依赖 | 说明 | 缓解 |
| --- | --- | --- |
| 01 与《v2 方案》漂移 | 两份文档同平台维护，tab 数/命名改动需同步 | 约定 v2=结构层、01=收敛层（01 §5），改动双更 |
| `app_theme.dart` / `ThemePreset` 被多人改动 | V 系列 + 高对比 + 转场化都动此核心 | 分批落地；第一批只改圆角/阴影/字阶，第二批改枚举与 `app.dart`；`ThemePalette` 类与 `lerp` 零改动 |
| 令牌替换涉及 `const` 拆除 | `TextStyle` 去 const 后需 context，改动面广 | 用 04 的「style 提升 + 正则筛查」批量处理，IDE 重构辅助 |
| `ErrorWidget.builder` 无 context | C-4 需取色但闭包无 BuildContext | 用 `Builder` 包裹或顶部共享 context widget 传递 |
| 分页字段不一致（`records` vs `list`） | 前端多页面读取路径混乱 | 统一 `PageResult.list`，service 层归一（I-7） |
| 后端过滤能力 | 无限滚动希望后端过滤而非本地全量 | 病例市场/错题接口补 `keyword/type` 参数（I-7） |

## 6. 量化验收指标

上线前用 `flutter run --profile` / Performance Overlay 核对：

| 指标 | 目标 |
| --- | --- |
| 按钮操作反馈延迟 | ≤ 100ms |
| 滚动帧 | 60fps，jank ≤ 0.5%，帧间隔 ≤16ms |
| 首屏可交互（TTFI） | 骨架 ≤200ms 出现，真实内容首帧 ≤1.5s |
| 深色文字 WCAG AA | text1~4 全 ≥ 4.5:1（正文）；text4 ≥ 4.7:1 |
| 装饰性硬编码 | `Color(0x…)`+`Colors.*` 直写 ≈ 0（语义锁色除外） |
| 病例入口数量 | 学生训练页同屏 4 个 → 主流程+总览去重 |

---

## 7. 结语

改版不动架构骨架（4 Tab、令牌体系、柔和转场都保留），核心是**四件事**：把四个病例入口的是非题收敛成一条动线、把"越叠越多"的装饰改成"做完减法"的克制、把一次性渲染改成无限滚动+骨架、把绕过令牌的硬编码全部收编并修好深色对比度。按「阶段 A 止血 → 阶段 B 收敛 → 阶段 C 增强」推进，预计能同时解决卡顿、廉价感与引导缺失三组反馈。

*总纲 v1.0 · 2026-08-27 · 索引四份专项方案，落地前以 01~04 详情为准。*

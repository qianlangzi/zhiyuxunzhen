# 智愈寻真 · 代码规范与性能修复方案

- 目标模块：`mobile/lib`（Flutter / Dart）
- 关联设计系统：`core/theme/app_colors.dart`、`core/theme/theme_preset.dart`、`core/theme/app_theme.dart`
- 文档定位：将「硬编码颜色、深色模式对比度、首屏渲染性能」三类问题统一收敛到既有语义取色体系（`AppColors.*Of(context)` / `ThemePaletteExtension`）并面向首帧做性能治理。
- 背景：本应用已具备一套完整且正确的语义取色体系——`AppColors` 提供 `textOf / text2Of / text3Of / text4Of / surfaceOf / primaryOf / onPrimaryOf` 等上下文取色函数，取色源统一挂载在 `ThemePaletteExtension`；切换主题预设（本草 / 墨青 / 丹砂）或明暗模式时，全 App 颜色可统一切换、不串色。本次治理的目标是：**把所有绕过该体系、直接书写字面颜色的代码全部纳入体系**，同时修复深色模式下的对比度与首帧性能。

## 一、现状分析

### 1.1 硬编码颜色清单（取证）

按真实问题性质，把 `lib` 下所有 `Color(0x…)` / `Colors.xxx` / `Color.fromARGB` / `withOpacity` 使用分为四类：

- **① 令牌定义（合法，勿动）**：`app_colors.dart` 与 `theme_preset.dart` 内部的常量定义本身即是「唯一数据源」，是语义取色的来源，属于正确写法，不得改动。
- **② 语义令牌调用（合法，典型范式）**：形如 `AppColors.textOf(context)` / `surfaceOf(context)` 的调用（`settings_screen.dart`、`app_widgets.dart`、`profile_widgets.dart`、`feedback.dart`、`bottom_tab_bar.dart` 等），已正确走体系，作为**待对齐的样板**。
- **③ 装饰性硬编码（本次需修复）**：直接写出 `Color(0xFF…)` 或裸用 `Colors.white / black87 / grey / red` 等，绕过预设与明暗切换，是本次治理主体。
- **④ 静态别名字段（低危，可顺手收敛）**：`AppColors.moss / moss2 / moss3 / indigo / vermilion / amber` 等非「Of」静态常量被直接用于页内装饰。其中 `vermilion / amber / indigo`（错误 / 警告 / 信息语义色）为全 App 固定警示色，可保留；但 `moss / moss2 / moss3`（品牌间色）应改走 `primaryOf / onPrimarySoftOf` 等，否则切换预设后主色会变而这些间色不变，产生串色。

### 1.2 深色模式对比度风险点

以默认预设「本草」深色为基准，逐层核对既有令牌自身的 WCAG 对比度（相对亮度按 sRGB 线性化 + 加权计算约估）：

| 前景 | 背景 `bg #12161A` | 估算对比度 | WCAG AA 4.5:1 | 结论 |
|---|---|---|---|---|
| `text #EDF1EF` | 深底 | ≈ **15.9:1** | ✅ | 达标 |
| `text2 #C6CFCC` | 深底 | ≈ **11.4:1** | ✅ | 达标 |
| `text3 #9BA6A5` | 深底 | ≈ **7.3:1** | ✅ | 达标 |
| `text4 #737E7D` | 深底 | ≈ **4.3:1** | ⚠️ 略低于 4.5 | **正文小字不达标**，仅适合占位 / 禁用 |

结论：
1. **令牌层整体健康**：`text / text2 / text3` 在深色底上均远超 AA，说明 `theme_preset.dart` 的深色文字体系设计正确，无需大改。
2. **唯一薄弱**：深色 `text4 ≈ 4.3:1` 略低于 AA 普通文本门槛。`text4` 语义为「占位 / 禁用 / 弱图标」，作禁用态可豁免，但只要它被用作**正文辅助**（如 `case_market_screen.dart` 空态文案、`settings_screen.dart` 的辅助说明）就会踩线。建议将深色 `text4` 从 `#737E7D` 微提亮至 `#7E8987`（约 4.8:1）并保持全预设一致。
3. **真正的对比度事故集中在硬编码**：
   - `essay_review_screen.dart` 的 `Colors.black87` 落在深色 `vermilionSoft(#2C1B18)` 上，对比度≈不足 1.5:1 —— **完全不可读**，必须先修。
   - `Color(0xCCFFFFFF)` 落在 `primary` 上：浅色 primary(`#2D4A3E`) 上白色 ≈ 9:1 ✅；深色 primary(`#5A7A6B`) 上白色 ≈ 5.6:1 ✅ —— 达标，但为语义统一仍应换 `onPrimarySoftOf`。
   - `Color(0x147B1F0E)` 深色下分隔线几乎隐形，仅装饰性，低危。
4. **hero 白色建议**：`teacher_home_screen.dart` / `student_case_market_screen.dart` / `mistakes_screen.dart` / `ai_tutor_screen.dart` 等 hero 均以 `primaryOf → moss2` 渐变打底，白色前景对比在两个模式均达标；只要前景区统一为 `onPrimaryOf`，即可在主色随预设替换后依然稳定。

## 二、改进方案

### 2.1 设计令牌替换规则表

> 左侧为「现状字面量」，右侧为「统一后的取色方法」。所有替换均依赖 `BuildContext`，涉及 `const` 期望的 `TextStyle` 需显式传入 context 并去掉 `const`（见 3.1）。

| 现状硬编码 | 语义等价 | 统一替换为 |
|---|---|---|
| `Color(0xFF9AA09D)` | 生成预设 text4 | `AppColors.text4Of(context)` |
| `Color(0xFF6B7270)` | 生成预设 text3 | `AppColors.text3Of(context)` |
| `Color(0xCCFFFFFF)`（on-primary 80% 白） | 主色上次要文字 | `AppColors.onPrimaryLightOf(context)`；若需要 alpha 再 `.withValues(alpha: 0.85)` |
| `Colors.black87`（浅色卡正文） | 正文/辅助 | `AppColors.textOf(context)` / `text3Of(context)` |
| `Colors.black87`（朱砂软卡上正文） | 错误卡正文 | `AppColors.textOf(context)`，必要时 `.withValues(alpha: .9)` |
| `Colors.grey`（空态/辅助文案） | 占位文字 | `AppColors.text4Of(context)` |
| `Colors.black`（消息/遮罩文本） | 正文 | `AppColors.textOf(context)`（遮罩另见 2.2） |
| `Colors.white`（hero / on-primary） | 主色之上前景 | `AppColors.onPrimaryOf(context)` |
| `Colors.white.withValues(alpha: x)`（hero overlay） | 主色派生高光/蒙层 | `AppColors.primaryOf(context).withValues(alpha: x)` 或 `onPrimaryOf.withValues` |
| `Colors.red`（错误图标） | 错误语义 | `AppColors.error` / `AppColors.vermilion` |
| `Color(0x147B1F0E)`（朱砂分隔线） | 错误软色分隔 | `AppColors.vermilion.withValues(alpha: 0.4)`，背景改 `vermilionSoftOf(context)` |
| `AppColors.moss / moss2 / moss3`（品牌间色装饰） | 主色系 | `AppColors.primaryOf(context)` / `onPrimarySoftOf(context)` |
| `AppColors.mossStrong`·科室封面色三元组 `Color(0xFF…)` | 病例封面色板 | 收编为 `ThemePalette` 内 `caseCover`（或 `Color.lerp(primaryOf, bgOf)` 派生），随预设/深色自适应 |
| `AppColors.vermilion / amber / indigo`（警示/信息锁色） | 全局语义固定色 | **保留**（不随主题，属正确用法） |
| `app_colors.dart / theme_preset.dart` 内 `Color(0x…)` | 令牌定义 | 保留不动（唯一数据源） |

### 2.3 首屏性能优化

1. **惰性列表 + 骨架屏**：首屏（`student_home`、`teacher/dashboard` 等）由 `SingleChildScrollView + Column` 一次性铺开，改为：
   - 上屏即渲染的**首屏骨架**（`Shimmer` 或静态 `AppColors.surfaceOf` 圆角块）；
   - 数据到位后用**惰性滚动**（`ListView.builder` / `CustomScrollView + SliverList`）分段渲染，避免先整页 build 再填充数据。
2. **图片缩小 + 骨架占位 + 缓存**：全库网络图统一 `CachedNetworkImage`（依赖已具备，见 3.2），配 `placeholder`/`errorWidget`；封面上传时在后端/CDN 侧生成「缩略图尺寸」（如 320px 宽 WebP）再下发，客户端 `BoxFit` 展示，禁止拉原图。
3. **const 优化与最小化 rebuild**：
   - 恒定子树抽 `const`（图标、纯文本、装饰容器），把 `TextStyle` 尽量提到最外层常量；
   - 回填数据后**只刷新局部 Provider/State**（如仅热力图、仅列表），不要用一层 `setState` 重建整页；
   - 将 `_buildGreeting / _buildSearchBar / _buildHeatmap` 等拆成独立 widget/ValueNotifier，缓存不随父重建的单位。
4. **重排列表治理**：`class_manage_screen.dart` 的 `ReorderableListView.builder` 给每项配稳定 `Key`（模型 id），避免重排时无谓重建全部卡片。
5. **图片像素尺寸**：`captcha_widget.dart` 显式 `width:96/height:40` 已合理；其余 Hero 图若由网络下发需强制缩缩写位避免解码超大图。

```dart
// 方案：CustomScrollView + SliverList 惰性渲染；骨架屏先行
return Scaffold(
  backgroundColor: AppColors.bgOf(context),
  body: SafeArea(
    child: RefreshIndicator(
      onRefresh: _loadData,
      child: CustomScrollView(
        physics: const AlwaysScrollableScrollPhysics(),
        slivers: [
          SliverToBoxAdapter(child: _buildGreeting(user) /* const 化的静态问候 */),
          const SliverToBoxAdapter(child: SizedBox(height: 20)),
          SliverToBoxAdapter(child: _buildSearchBar()),             // const/独立态
          SliverToBoxAdapter(child: _buildHeatmap()),               // 仅此块 setState
          SliverList.builder(                                       // 惰性：只建可视项
            itemCount: _tasks.length,
            itemBuilder: (context, i) => _TaskCard(
              key: ValueKey(_tasks[i].id),                          // 稳定 key，重排/差异化复用
              task: _tasks[i],
            ),
          ),
          const SliverToBoxAdapter(child: SizedBox(height: 16)),
        ],
      ),
    ),
  ),
);
```

配套降载要点：

- 首帧先渲染**骨架**（若干 `AppColors.surfaceOf` 占位圆角块），数据返回后仅替换数据区，减少首帧等待。
- `_buildHeatmap()` 改为接收数据变化的 `ValueListenable`，避免整页重建。
- 所有图标/纯装饰子树补 `const`，`TextStyle` 提升为常量。
- `class_manage_screen.dart` 的 `ReorderableListView.builder` 每项加 `ValueKey(model.id)`。

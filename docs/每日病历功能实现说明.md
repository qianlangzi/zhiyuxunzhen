# 每日病历功能实现说明（v1.0 · 2026-09-06）

> 每日一例升级版：把「看病例答一段」升级为 LeetCode 式「每日病历」——
> 九段书写 + AI 段落教练 + 结构化批阅 + 缺陷沉淀 + 题库回看 + 打卡日历，并打通教师端复核闭环。

---

## 一、怎么用

### 学生端

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| 1 | 首页点原「每日一例」入口 | 路由不变，进入新的「每日病历」首页 |
| 2 | 看今日卡 | 病例标题/难度/科室/患者画像 + **连续打卡天数** |
| 3 | 点「开始书写」 | 进入**书写工坊**：九段（主诉→现病史→既往史→查体→辅检→诊断→依据→鉴别→计划），每段有规范提示 |
| 4 | 卡住点段内「问 AI」 | 三级提示梯度：**第 1 次=追问**（不给答案）→ **第 2 次=定向提示** → **第 3 次=示范片段**（带"禁止照抄"警示）；AI 还会从问诊原话里**回捞素材** |
| 5 | 点「提交病历 · AI 批阅」 | 秒级返回：总分 + 九段得分条 + 逐条缺陷（如"主诉 27 字超规范，建议压缩"）+ AI 总评 |
| 6 | 「再写一版」修订迭代 | 同一病例可多次提交，每版独立存档打分，报告页可切版本对比 |
| 7 | 提交后解锁 | 标准诊断要点与参考病历**提交过才下发**（防照抄） |
| 8 | 「病历题库」 | 往期全部病例，可筛「未完成/已完成」，补写或回看报告 |
| 9 | 「打卡日历」 | 全年打卡格 + 连续天数 + 累计完成数（今天没做不断签，隔天归零） |

### 教师端

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| 1 | 工作台 → 新增「**每日病历批阅台**」卡片 | 在"教材管理/基础题库"下方 |
| 2 | 「批阅台」Tab 选期次 | 学生列表按"建议复核"优先排序；AI 置信度 ≥0.85 显示"**AI 高置信**"（可免复核），低置信显示"**建议复核**" |
| 3 | 点学生卡 | 弹层看 AI 总评 + 缺陷标签，可**改最终分 + 写评语**（教师分覆盖 AI 分，学生端显示"教师已复核"） |
| 4 | 「缺陷热力」Tab | 全班缺陷聚合条形图（次数 + 人数），红色 = 共性短板（如"全班漏既往史"），直接作为讲评素材 |

## 二、复用了项目里哪些能力（未造轮子清单）

| 复用项 | 位置 | 怎么用的 |
| --- | --- | --- |
| **Agent 网关 + 分组门面** | `ai/app/api/agent_gateway.py` + `agents/gateway_features.py` | 新能力注册进 evaluator 分组（`mr_hint`/`mr_review` 两个 action），鉴权、降级、模型参数全部沿用现有链路 |
| **评测批阅 Agent 分组** | `EvaluatorClient` → `/internal/agent/evaluator` | 后端只加两个方法，走同一 HTTP 门面 |
| **每日一例排期引擎** | `DailyCaseServiceImpl.today()` | 0 点 cron 自动排期 + Redis 全局缓存 + "缓存日期非当天即重排"兜底，**原样复用**，每日病历只在其上叠加 |
| **LLM 客户端 / 模型网关** | `llm_client.chat_json`（DeepSeek） | 教练与批阅都是 JSON 模式调用 |
| **教材 RAG** | `rag_service.search` | 批阅时检索《内科学》原文作评分锚点（失败静默降级，与 essay_review 同策略） |
| **提示词配置中心** | `_system_prompt` / `baseline_prompts` | 新 prompt `mr_coach`/`mr_reviewer` 自动进管理端基线，可在线热调 |
| **MyBatis-Plus / PageResult / UserContext / 审计** | 后端基础设施 | 实体只继承 BaseEntity |
| **移动端组件体系** | `AppBackAppBar/AppCard/AppPrimaryButton/PressableScale/AppColors.*Of(context)` | 深浅色主题自动适配，零硬编码颜色 |

## 三、新增接口

### AI 中台（`ai/app/api/mr.py`，可直连亦可走网关）

| 接口 | 说明 |
| --- | --- |
| `POST /mr/segment_hint` | 段落教练：三级提示梯度 + 问诊素材回捞，**绝不代写** |
| `POST /mr/review_record` | 结构化批阅：九段独立评分 + 缺陷标签打标（28 种）+ 置信度 + 总评 |

### 业务中台 · 学生端 `/api/v1/student/daily-cases/mr/*`

| 接口 | 说明 |
| --- | --- |
| `GET /today` | 今日卡：排期 + 我的最新记录 + 连续打卡 |
| `GET /bank` | 病历题库（分页 + done 筛选：全部/未做/已做） |
| `GET /{scheduleId}` | 题目详情：病例材料 + 九段定义 + 我的提交版本；**提交过才下发标准答案/参考病历** |
| `POST /hint` | 段落教练（AI，走 evaluator 网关） |
| `POST /submit` | 提交九段 → AI 批阅 → 落 record/segment/defect 三表 |
| `GET /calendar` | 打卡日历（年份 + 全部打卡日 + streak） |

### 业务中台 · 教师端 `/api/v1/teacher/daily-cases/mr/*`

| 接口 | 说明 |
| --- | --- |
| `GET /schedules` | 最近期次列表（选期用） |
| `GET /records` | 批阅台列表（AI 分/置信度/needReview 标记） |
| `PATCH /records/{id}/review` | 教师复核：最终分 + 评语 |
| `GET /defect-stats` | 班级缺陷聚合（tag_code/次数/人数） |

## 四、数据模型（V43 迁移，Flyway 部署后自动执行）

- `daily_case_schedule` 扩展：`case_summary` / `difficulty` / `system_tag` / `writing_mode` / `reference_record`
- 新表 `daily_case_record`（多版本病历 + AI 分/置信度 + 教师复核分）
- 新表 `daily_case_segment`（九段逐段存储 + 段级反馈）
- 新表 `mr_defect_tag`（28 条缺陷字典：CC_TOO_LONG、PE_NO_NEGATIVE、DDX_INSUFFICIENT…）
- 新表 `daily_case_defect`（缺陷命中流水 = 学生画像与班级热力图数据源）

全部幂等增量写法（information_schema 判重），不含任何 DROP/DELETE。

## 六、部署与验证

1. 后端：`mvn package` → dev 环境 `docker-compose restart backend`（jar 热替换）；prod 服务器 `docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`
2. Flyway 启动自动执行 V43（日志可见 `Successfully applied ... V43`）
3. AI：`ai` 容器 bind mount + `--reload` 自动生效；**`ai-worker` 无源码挂载，需要 `docker-compose build ai-worker && docker-compose up -d ai-worker`**（最容易漏）
4. 移动端：`dart analyze` 已通过（0 error 0 warning），正常跑 `flutter run`
5. 验证链路：学生端提交一份病历 → 看 `daily_case_record/segment/defect` 三表有数据 → 教师端批阅台可见 → 复核改分 → 学生报告页显示"教师已复核"

## 三、🔴 P0 阻断上线问题（4 项）

### P0-1：AI 核心功能整体不可用（LLM 未配置）

**现象**（实测，非猜测）：
- `POST /api/v1/student/learning-path/generate` → `{"code":503,"message":"当前 AI 服务暂不可用"}`
- `GET /api/v1/teacher/ai/class-insight` → `{"code":500,"message":"AI 暂不可用，无法生成学情洞察"}`
- `GET /api/v1/teacher/ai/recommend-cases` → `{"code":5000,"message":"系统内部错误"}`
- AI 日志：`LLM 未配置或不可用，使用规则降级`、`event=learning_path_unavailable code=AI_UNAVAILABLE`

**根因**：
- `docker inspect zhiyu-ai` 显示 `LLM_BASE_URL=`（**空**）、`LLM_API_KEY` 有值但 `LLM_BASE_URL` 为空 → `settings.llm_configured = false` → 所有依赖 LLM 的接口不可用
- `.env` 里只配了 `LLM_API_KEY`，**没有配 `LLM_BASE_URL`**
- `ENABLE_LLM_FALLBACK=false`（生产正确姿势，但开发环境也没开降级）

**影响面**：学习路径生成、AI 病例推荐、学情洞察、病例草稿、质量检查、AI 评语、对话问诊（AI 回复）——所有 AI 能力全部失效。

**修复**：
```bash
# 在 E:\zhiyu\.env 补充（以 DeepSeek 为例）：
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
# 确认 LLM_API_KEY 已填真实 Key
```
改完重启：`docker compose up -d --build ai ai-worker backend`

### P0-2：教材电子书无法阅读（PDF 文件不存在 + 资源映射缺失）

**现象**（实测）：
- 教材列表/详情接口正常返回 6 本书（内科学、诊断学、病理生理学、药理学等）
- 但 `GET http://localhost:18080/ebook/1.pdf` → **500**
- 后端容器 `/app` 下**没有任何 PDF 文件**，也没有 uploads 目录

**根因**：
1. 数据库 `textbook.file_url = /ebook/1.pdf`，但后端**从未配置 `/ebook/**` 的静态资源映射**（WebMvcConfig 只映射了 `/uploads/**`）
2. 容器内没有 PDF 实体文件——这些教材记录疑似通过 SQL/初始化脚本写入，但文件从未上传到服务器

**影响面**：学生端「教材中心」点开任何一本书 → 白屏/报错。这是学生核心学习场景。

**修复**（三选一，推荐方案 A）：
- **A**：把 6 本教材 PDF 上传到后端 `uploads/ebooks/` 目录，并把数据库 file_url 改为 `/uploads/ebooks/xxx.pdf`（注意 WebMvcConfig 已映射 `/uploads/**`，需挂载持久化目录）
- **B**：在 WebMvcConfig 增加 `/ebook/**` 映射 + 把 PDF 放入容器
- **C**：教材改存 MinIO（已在跑），file_url 指向 MinIO 外链

### P0-3：数据库业务数据几乎全空（上线后无内容可用）

**实测数据盘点**：

| 表 | 数据量 | 影响 |
|------|------|------|
| teaching_class（班级） | **0** | 教师无法布置作业、无法建病例配置 |
| assignment / assignment_instance | **0** | 学生没有作业可做 |
| daily_case_schedule（每日病例） | **0** | 学生「每日病例」无内容 |
| sp_case_config（问诊病例） | **0** | 问诊训练无病例可启动 |
| chat_session / chat_message_log | **0** | 无历史会话 |
| case-market（病例市场） | **0** | 病例市场空 |
| sys_config | **0** | 系统配置缺失 |
| textbook | 6 | ✅ 有（但 PDF 文件缺失，见 P0-2） |
| practice_question | 33 | ✅ 有（仅 33 题，量偏少） |
| student_practice_record | 16 | 测试数据（你昨天答题产生的） |

**影响面**：教师登录后看到全是 0 的仪表盘、空班级列表；学生登录后每日病例、作业、病例市场全空——**新用户第一次打开会认为产品是坏的**。

**修复**：上线前必须准备种子数据：至少 3-5 个班级、若干作业、每日病例排期、问诊病例（含 SP 配置）、病例市场内容。题库 33 题偏少，建议扩充到 200+。

### P0-4：短信服务未配置（注册/短信登录无法工作）

**现象**（代码审查）：
- `application.yml`：`zhiyu.sms.provider=`（空）、`SMS_JUHE_KEY` 未配置
- `RedisSmsCodeService.sendCode()`：非 dev 环境若 provider 为空 → `短信厂商发送器尚未配置`
- 当前 dev 环境靠"验证码回显"联调（接口返回 code），**上线即失效**

**影响面**：学生注册（强制手机号验证）、短信登录全部不可用。

**修复**：配置聚合数据（juhe.cn）短信：`.env` 加 `SMS_PROVIDER=juhe`、`SMS_JUHE_KEY=xxx`（模板 ID 已有默认值）。上线前用真实手机号完整走一遍注册流程。

## 四、🟠 P1 上线前必修问题（8 项）

### P1-1：上传文件不持久化（容器重启即丢）
- `zhiyu.upload.dir=./uploads` 指容器内路径，**docker-compose 未挂载宿主目录**
- 教师上传的资质证书、病例图片、教材 PDF 存在容器内，`docker compose down` 后全部丢失
- **修复**：compose 里给 backend 加 `./data/uploads:/app/uploads` 挂载（参考 mysql 的挂载方式）

### P1-2：教师端关键功能无数据可用
- `GET /api/v1/teacher/dashboard/overview` → 全 0
- `GET /api/v1/teacher/assignments`、`/classes`、`/cases` → 全空
- `GET /api/v1/teacher/textbooks` → **空**（学生端有 6 本，教师端列表为空！疑似查询条件问题）
- **修复**：核对 TeacherTextbookServiceImpl 的查询条件；补充教师侧演示数据

### P1-3：移动端登录页测试模式残留
- `login_screen.dart:410-413`：手机号格式校验**被注释**（"测试模式"）
- `login_screen.dart:429-432`：验证码正确性校验**被注释**
- **风险**：上线后任意格式手机号可提交、验证码不校验（后端会校验，但前端体验和风控缺失）
- **修复**：恢复两处校验代码

### P1-4：AI 全链路未联调（依赖 P0-1）
- 学生问诊对话（`/sessions/{id}/chat`）、影像分析（`/image/analyze`）、每日病例判题、报告生成均依赖 AI 服务
- 当前 AI 服务 LLM 未配置，上述功能要么 503、要么走降级返回假数据（chat_room_screen 有硬编码 fallback 对话）
- **风险**：学生问诊训练是产品核心场景，降级假对话一旦被当成真实功能上线后果严重
- **修复**：P0-1 修复后，用真实账号走通「启动会话 → 对话 → 影像上传 → 分析 → 结束 → 报告」全链路

### P1-5：每日病例功能无排期数据（依赖 P0-3）
- `GET /api/v1/student/daily-cases/today` → `data:null`（无排期）
- `POST /daily-cases/submit` → `1404 排期不存在`
- 学生端「每日一例」入口实际不可用

### P1-6：病例市场/病例配置无数据（依赖 P0-3）
- `GET /api/v1/case-market/list` → 空列表
- `sp_case_config` 表为 0 → 教师端「SP 病例配置」无法新建有效病例

### P1-7：移动端 API 地址为模拟器默认值，真机需手动注入
- `api_config.dart` 默认 `http://10.0.2.2:18080`（Android 模拟器）
- 真机部署必须 `--dart-define=API_BASE_URL=http://<服务器IP>:18080` 重新构建
- **风险**：如果线上服务器是 HTTPS 域名，当前代码用 `usesCleartextTraffic="true"` 明文 HTTP，**生产环境必须上 HTTPS**，否则有安全合规风险
- **修复**：确认上线域名 + HTTPS；Android 正式包建议移除明文流量开关，改用 network security config

### P1-8：教师注册审核流程未验证
- 教师注册需上传资质证书（`POST /api/v1/auth/upload` → 存 `./uploads/certificates`，见 P1-1 不持久化）
- 教师注册后 `audit_status=1` 待审核，需管理员审核才能登录（当前 admin01 可用）
- 上线前需要走通：教师注册 → 管理员审核 → 教师登录 全流程

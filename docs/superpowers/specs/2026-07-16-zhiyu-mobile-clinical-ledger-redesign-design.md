# 智愈寻真移动端「临床刊物」重构设计

日期：2026-07-16

范围：`mobile/` Flutter 学生端与教师端

状态：规格已确认，待实施

预览方向：Clinical Ledger / 临床刊物与精密工作台

## 1. 决策摘要

本设计以用户选择的「教学中控台」方向为基础，保留高信息密度、行动队列和状态可扫描性，同时去除通用 AI 仪表盘的视觉特征。最终界面不依赖渐变、玻璃效果、大指标卡、胶囊标签或整屏青绿色，而以病例、证据、批阅记录、细分隔线和明确排版建立专业感。

本文件更新并取代 `2026-07-15-zhiyu-mobile-user-redesign-design.md` 的视觉系统与页面表现章节。原文档中的业务范围、身份分流、路由守卫、数据模型、交互状态、可访问性和响应式要求继续有效，除非本文件明确修改。

## 2. 目标与非目标

### 2.1 目标

1. 重构全部 Flutter 用户界面，包括统一登录、学生端、教师端和共享组件。
2. 让学生快速识别当前病例、缺失证据和下一步训练动作。
3. 让教师快速扫描批阅风险、截止时间、争议项和班级进度。
4. 建立同一套有产品识别度的视觉系统，不将两种身份做成两套 App。
5. 保留现有业务行为，并交付可安装到 Android 手机的通用 Release APK。

### 2.2 非目标

- 不修改 `front/` Web 管理端。
- 不重构后端、AI 服务、Repository、数据模型或角色权限规则。
- 不新增真实患者数据、远端埋点或第三方服务。
- 不为视觉效果增加营销页、装饰插画、氛围图片或循环动画。
- 不在本轮接入生产签名；APK 用于本地安装与视觉验收。

## 3. 设计语言

### 3.1 物理场景

用户在白天的教室、示教室、门诊或办公室中反复使用应用，需要在短时间内阅读临床信息并做决定。因此采用亮色、高对比、低装饰的界面，不采用大面积暗色，也不使用偏暖纸张色模拟传统病历。

### 3.2 核心隐喻

界面像一本由临床教师编辑的数字刊物，而不是 SaaS 数据大屏：

- 页面由标题、病例编号、时间、细线和记录行组织。
- 颜色只表达动作与状态，不负责填满表面。
- 病例、证据和批阅对象以连续记录呈现，不拆成等宽卡片阵列。
- 每个页面最多有一个高强调主动作。

### 3.3 识别元素：临床证据轴

学生端和教师端共用「临床证据轴」：

- 学生端串联已询问信息、缺失危险因素、支持证据、反对证据和待确认项。
- 教师端串联学生判断、AI 评分依据、教师复核意见和最终处理结果。
- 证据轴使用 1px 纵向规则和小型状态节点，不使用粗侧边彩条。
- 节点必须配文字状态，不能只靠颜色表达含义。

## 4. 视觉系统

### 4.1 色彩

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#F7F7F5` | 中性近白背景 |
| 主表面 | `#FFFFFF` | 输入区、弹层和必要独立表面 |
| 主文字 | `#171B1D` | 标题、正文、主导航 |
| 次文字 | `#40484B` | 说明与次级信息 |
| 弱文字 | `#6C7477` | 时间、编号和辅助信息 |
| 细线 | `#CFD4D5` | 列表与分区规则 |
| 强线 | `#8D9598` | 重要分区边界 |
| 行动蓝 | `#24508C` | 主操作、当前导航、可交互重点 |
| 风险红 | `#B73B32` | 争议、风险、错误和必须处理项 |
| 通过绿 | `#26705D` | 完成、通过和稳定状态 |

规则：

- 页面不使用渐变、发光、玻璃模糊或装饰色块。
- 行动蓝不铺满整屏，只用于主操作、当前导航和少量信息索引。
- 风险红和通过绿只表达真实业务状态。
- 普通内容不使用彩色浅底卡片；状态可用小面积文字、图标或节点表达。

### 4.2 排版

- 中文正文使用平台稳定的系统无衬线字体，保证 Android 可读性和 APK 体积。
- 产品名、页面主标题和病例主标题使用 Android 系统衬线族，并配置系统无衬线回退；正文、按钮、表单和导航仍使用无衬线字体。
- 页面主标题通过字体对比、字重、行高和留白形成刊物感，不依赖超大字号；手机端为 `24-28px`。
- 病例标题和关键结论为 `17-20px`，正文为 `15-16px`，辅助信息为 `12-13px`。
- 编号、时间、比分和比例使用等宽数字特性，避免数据变化引起布局跳动。
- 中文不使用负字距，不在应用界面中堆叠装饰性英文大写栏目名。
- 第一版 APK 不引入大型中文字体包。构建后必须在 Android 预览中确认衬线标题回退正常；若目标手机无法得到稳定中文字形，则统一回退到系统无衬线，不在本轮临时加入网络字体。

### 4.3 形状、表面与阴影

- 普通页面区块默认无容器、无背景、无阴影，使用标题、留白和细线分组。
- 独立可点击病例或批阅对象允许 `4-6px` 小圆角；表单控件为 `8px`；底部弹层为 `16px`。
- 底部导航、固定操作栏和弹层允许一层极轻阴影，正文列表不用阴影。
- 胶囊只用于极短、可切换的二元状态；普通状态标签为小圆角文字标记。
- 不允许卡片套卡片，也不允许用三个等宽指标卡占据首屏。

### 4.4 图标与品牌

- 保留 `mobile/assets/images/brand-logo.png`，不重绘、不变色、不变形。
- 登录页使用现有 Logo；应用内部以「智愈寻真」文字标识和紧凑日期/身份信息构成页眉。
- 图标继续使用 Flutter Material 图标，统一为线性或同一视觉重量。
- 熟悉操作可使用图标按钮并提供 Tooltip/Semantics；关键命令使用图标加中文文字。

## 5. 共享界面结构

### 5.1 应用页眉

页眉由产品标识、当前页面标题、必要日期或身份信息组成。二级页面保留返回按钮。页眉不使用大面积深色背景，不重复显示无意义的栏目眉题。

### 5.2 分区标题

分区标题使用标题、可选说明和 1px 下规则。右侧只放一个与整组内容有关的操作，避免每行出现多个低频按钮。

### 5.3 记录行

病例、任务、反馈和批阅队列采用可扫描记录行：时间或编号、主内容、状态三列。整行作为一个触控目标，行高不低于 52px。

### 5.4 主操作

每页最多一个高强调主操作。滚动长页可使用安全区域上方的稳定操作栏，但不得遮挡正文或底部导航。

### 5.5 底部导航

学生端与教师端各保留五个入口。导航使用图标、短中文和底部选中指示，不使用大胶囊背景。导航高度稳定并尊重 SafeArea。

## 6. 页面方案

### 6.1 统一登录

- 保留 Logo、产品名、账号和密码表单。
- 教师/学生演示身份使用紧凑分段控制，不渲染成两张身份卡。
- 输入框有可见标签、错误信息、密码显隐和提交加载状态。
- 不增加营销文案、装饰图形或渐变背景。

### 6.2 学生首页

- 页眉显示简短问候和日期。
- 第一屏主体是当前病例记录：病例编号、病人概况、科室、难度、进度和剩余时间。
- 下方临床证据轴列出已记录、待补问和高风险信息。
- 唯一主操作为「继续完成问诊」。最近反馈和复盘内容以记录行展示。

### 6.3 病例列表与详情

- 搜索和筛选采用紧凑工具栏；筛选结果为纵向记录行。
- 病例详情按患者概况、训练目标、已有资料和注意事项组织。
- 「开始问诊」位于稳定底部操作区。

### 6.4 问诊室

- 保持患者消息、学生消息和导师提示的角色区分。
- 顶部患者摘要压缩为单行或两行记录，不占用大量对话空间。
- 模式切换使用分段控制；输入和发送始终位于安全区域上方。
- 思维路径抽屉使用证据轴表达推理节点，与学生首页保持一致。

### 6.5 反馈与复盘

- 先呈现一句可行动结论，再呈现能力维度和具体证据。
- 能力数据使用规则行、条形进度和文字，不使用装饰雷达图。
- 复盘项直接展示错误依据、病例来源、状态和下一步动作。

### 6.6 学生「我的」

- 保留身份信息、学习概况和三个月训练热力图。
- 热力图继续使用紧凑方格，不套厚重卡片。
- 账号与退出操作置于页面末尾，避免与学习内容竞争。

### 6.7 教师概览

- 页眉直接说明「今天需要处理的事」。
- 待复核、风险争议和班级完成率放在一条紧凑统计带中，不拆成三张卡。
- 当前 `ReviewItem` 没有截止时间字段，批阅登记按「争议 > 待复核 > 其他」风险/状态排序，同风险保持 Repository 原顺序；未来接口提供截止时间后再加入时限排序。
- 记录行显示模型已有的学生、作业、问题、分数和状态，不为设计稿伪造时间或证据字段。
- 唯一主操作为「处理最高风险记录」。

### 6.8 病例配置、病例广场与作业

- 病例配置继续使用独立表单页面，字段分组依靠分区标题和留白。
- 病例广场与作业使用纵向记录行，进度和状态保持可扫描。
- 创建、保存和引用等关键命令使用明确中文，不堆叠图标按钮。

### 6.9 批阅

- 主页面为按风险排序的批阅登记。
- 详情底部层展示学生答案、AI 依据、教师意见和临床证据轴。
- 「通过」和「退回修改」为清楚的互斥操作，处理后立即更新队列状态。

### 6.10 教师「我的」

- 与学生端共享身份区和记录行结构。
- 展示所属信息、教学概况和账号操作，不展示学生训练热力图。

## 7. 代码边界

保留现有 Riverpod、go_router、Repository、数据模型和角色守卫。重构仅改变展示层、主题和必要的局部 UI 状态。

共享层重点调整：

- `AppColors`、`AppTextStyles`、`AppDimens` 和 `AppTheme`。
- `ZyAppBar` / 页面页眉、`ZyBottomBar`、分区标题、记录行和状态标记。
- 新增领域明确的临床证据轴和批阅登记组件。
- `ZyCard` 保留给真正独立的可操作对象，不作为默认页面容器。

不新增万能配置组件，也不将学生和教师业务组件强行合并。

## 8. 状态、错误与动效

- 加载使用匹配最终结构的骨架行，不使用全屏中央转圈。
- 空状态说明原因并提供一个下一步操作。
- 表单错误靠近字段；页面错误保留原结构并提供「重新加载」。
- 成功提示短而明确，不打断任务。
- 页面和底部层转场为 `180-220ms`，使用 Flutter 原生淡入/位移。
- 状态变化不动画宽高；系统减少动态效果开启时禁用非必要转场。

## 9. 可访问性与响应式

- 触控目标不小于 44px。
- 正文对比度达到 WCAG AA，弱文字仍需可读。
- 颜色不作为唯一状态表达。
- 图标按钮具有 Semantics/Tooltip 名称。
- 在 `360×800`、`390×844`、`430×932` 手机竖屏和常见平板宽度下无溢出。
- 字体缩放 1.3 倍时主要任务、表单和批阅操作仍可完成。
- 软键盘出现时登录与问诊输入区保持可见。

### 10.1 自动化

- 现有 61 个测试必须继续通过。
- 更新主题、登录页、学生首页、教师概览和共享组件的测试断言。

### 10.2 浏览器与截图

- 使用 Flutter Web 预览检查登录、学生首页、病例列表、问诊、反馈、学生「我的」、教师概览、作业、批阅和教师「我的」。
- 至少在 360、390 和 430 三种宽度截图检查。
- 检查控制台错误、文字溢出、底部导航遮挡、状态对比和交互可达性。

### 10.3 Android APK

- 构建通用 Android Release APK，目标输出为 `mobile/build/app/outputs/flutter-apk/app-release.apk`。
- APK 启动后默认使用现有 Mock 数据，不依赖本机后端即可浏览主要流程。
- 演示账号保持 `student01 / 123456` 与 `teacher01 / 123456`。
- 在交付前记录 APK 大小与 SHA-256，并校验 APK 压缩结构、签名、包名、应用名和启动 Activity。
- 当前工作机没有 ADB、Android 模拟器或连接真机；安装与冷启动由用户在目标手机上完成最终验收，不在本地伪报为已验证。

## 11. 完成标准

1. 所有学生端、教师端和登录页面使用新的临床刊物视觉系统。
2. 页面不存在大面积渐变、玻璃效果、卡片套卡片、整屏青色或三个等宽首屏指标卡。
3. 学生首页和教师概览分别呈现已确认设计稿中的病例证据轴与批阅登记结构。
4. 现有登录、角色分流、导航、问诊、筛选、保存、批阅和退出功能保持有效。
5. `flutter analyze` 无错误，完整测试通过。
6. 通用 Release APK 成功生成，通过结构、签名和 Manifest 校验，并提供可下载路径、文件大小和 SHA-256；目标手机安装与冷启动结果由用户确认。

## 12. 实施顺序

1. 视觉 tokens、主题和共享结构。
2. 登录与两端应用壳。
3. 学生首页、病例、问诊、反馈、复盘和个人页。
4. 教师概览、病例、作业、批阅和个人页。
5. 全量测试、Web 多尺寸截图、视觉修正。
6. Android Release APK 构建与文件校验。

每个阶段完成后保持项目可分析、可测试、可预览。正式实现不得覆盖工作区中与本设计无关的用户修改。

# 智愈寻真角色化前端 MVP 设计规格

日期：2026-06-15  
范围：`front` 目录内的 Vue 3 前端页面设计改造  
基准文档：`docs/PRD_V1.0.md`

## 1. 设计读法

这是一个面向高校内科学教学的 AI 协同训练平台。教师在高压临床工作后需要快速分发病例、批阅大病历、定位班级薄弱点；学生需要在安全环境中完成 SP 问诊、影像圈选、诊断反思和学习补救。

视觉方向采用「临床玻璃舱」为主：清透、克制、可信，使用冷白、玉青、深墨绿和轻量毛玻璃。学生问诊区域吸收「沉浸问诊室」：右侧实时思维树、流式对话、影像圈选和反思拦截要更有交互张力。

## 2. 本次范围

本次先完成角色化演示 MVP，不做完整业务闭环和真实后端联调。

改造文件：

- `front/src/App.vue`
- `front/src/views/Login.vue`
- `front/src/views/Home.vue`
- `front/src/styles/main.css`

保留现有技术栈：

- Vue 3
- Pinia
- Vue Router
- Element Plus
- ECharts / vue-echarts 作为后续图谱能力依赖

不新增重型 UI 框架，不迁移 Tailwind，不改变后端接口契约。当前页面用模拟数据展示 PRD 核心能力，后续可逐块替换为真实 API。

## 3. 信息架构

### 3.1 登录页

登录页应从普通表单升级为产品级入口：

- 左侧：品牌、产品定位、核心指标和可信气质。
- 右侧：毛玻璃登录面板。
- 提供教师和学生两个快速身份切换按钮。
- 默认账号保留 `teacher01 / 123456` 与 `student01 / 123456`。
- 登录成功后继续写入现有 Pinia/localStorage 的 `token`、`username`、`role`。

登录页不做营销长页，首屏即为可用入口。

### 3.2 全局框架

全局框架应有清晰的产品壳层：

- 顶部玻璃导航：品牌、角色、当前用户、服务状态、退出。
- 主内容区：根据角色显示不同工作台。
- 底部固定免责声明：符合 PRD 9.2，文案为「系统提供内容仅供医学思维训练，不具备真实临床诊疗效力。」
- 页面最小高度使用动态视口单位，避免移动/Pad 浏览器跳动。

### 3.3 学生端工作台

学生端目标是让用户一进来就知道下一步训练什么。

核心区块：

- 今日 SP 病例：显示病例标题、主诉、知识点标签、预计训练时长、开始问诊按钮。
- 沉浸问诊室预览：左侧对话流，右侧实时临床思维树。
- 多模态影像卡片：上传影像、圈选异常点、输出相对坐标的能力提示。
- OSCE 四维反馈：病史采集、诊断逻辑、沟通技巧、人文关怀。
- 个性化学习路径：基于薄弱点展示补救路径和资源。
- 大病历提交：展示 5000 字上限、AI 异步批阅状态和提交入口。

交互：

- 主要模块可折叠。
- 问诊室预览内有状态反馈，如「流式连接中」「Mentor 反思提示」「tree event 已同步」。
- 影像圈选以预览态呈现，不在本次实现完整 Canvas 绘制逻辑。

### 3.4 教师端工作台

教师端目标是减少批改和分发成本。

核心区块：

- SP 零代码配置台：主诉、年龄、真实诊断、性格、知识点标签、预设检查。
- 作业分发：病例、班级、截止时间、是否要求大病历。
- AI 批阅队列：提交数、平均分、待复核、争议项。
- 人工复核面板：AI 标注错误、扣分项、教师覆盖结果。
- 班级薄弱点：聚合展示 AVG / COUNT，不展示敏感个人信息。
- 服务健康：Spring Boot、MySQL、AI 中台状态。

交互：

- 主要模块可折叠。
- 批阅队列支持选择样例记录后在右侧查看复核细节。
- SP 配置表单保留「知识点最多 5 个」提示。
- 作业和批阅动作在本次实现中以视觉反馈为主，不调用真实创建接口。

## 4. 视觉系统

### 4.1 主题

采用单一浅色主题，避免页面中途切换成大面积深色区块。局部深色只用于学生端问诊室和思维树，作为临床沉浸容器。

推荐色彩：

- 背景：冷白 `#f4f8f7`
- 主墨色：`#10231f`
- 次级文字：`#536862`
- 品牌色：深玉青 `#0f766e`
- 强调色：医疗青 `#14b8a6`
- 风险色：`#e05757`
- 玻璃面：`rgba(255, 255, 255, 0.68)`

只保留一个主强调色系，避免紫蓝 AI 渐变感。

### 4.2 字体

不新增字体依赖，优先使用系统中文字体并调好层级：

- 中文：`PingFang SC`, `Microsoft YaHei`
- 西文与数字：`SF Pro Display`, `Segoe UI`
- 数据：启用 `font-variant-numeric: tabular-nums`

标题使用 `text-wrap: balance`，正文使用 `text-wrap: pretty`。避免过密字距，不使用大面积全大写。

### 4.3 形态与材质

- 主容器圆角控制在 20-28px。
- 内部控件圆角控制在 12-16px。
- 按钮可使用胶囊形态。
- 毛玻璃只用于导航、登录面板、重点模块，不铺满所有卡片。
- 阴影使用带绿色调的透明阴影，避免纯黑厚阴影。

### 4.4 动效

动效只服务状态和层级：

- 登录卡片入场：轻微位移和透明度。
- 模块折叠：使用 Element Plus 原生折叠动效。
- 可点击卡片：hover 上浮 2px，active 下压 1px。
- 问诊流式状态：用低频光标/状态点表达，不做大面积循环动画。
- 尊重 `prefers-reduced-motion`。

## 5. 组件与数据

### 5.1 模拟数据

页面应内置演示数据：

- 学生病例：COPD 急性加重、胸痛待查、消化道出血。
- 学生薄弱点：心衰、肺水肿、胸痛鉴别、血常规判读。
- 教师作业：内科问诊训练 01、胸痛鉴别诊断、消化系统大病历。
- 批阅错误：现病史遗漏、检查逻辑缺失、诊断推理偏差。
- 服务健康：后端、数据库、AI 中台。

### 5.2 API 边界

保留现有健康检查请求：

- `/api/v1/health`
- `/ai/health`

登录仍优先尝试现有接口：

- `/api/v1/user/login`

如接口不可用，可在前端保留友好的错误提示，但不伪造真实鉴权。演示数据用于页面渲染，不代表真实提交成功。

## 6. 可访问性与响应式

本 MVP 主要适配 PC / Pad，符合 PRD 6.3。

要求：

- 关键按钮有明确文本，不只依赖图标。
- 文字对比度达到可读标准。
- 表单错误或限制提示出现在操作附近。
- 不阻止粘贴。
- 页面在 1024px 宽度仍不横向溢出。
- 小屏手机不作为优先目标，但应保持可滚动和不重叠。

## 7. 验收标准

完成后应满足：

- 登录页具备产品级视觉，不再是默认 Element Plus 卡片。
- 登录后能按 `role=0` 显示学生端，按 `role=1` 显示教师端。
- 学生端清楚体现问诊、影像圈选、思维树、OSCE、学习路径、大病历提交。
- 教师端清楚体现 SP 配置、作业分发、AI 批阅、人工复核、班级薄弱点、服务健康。
- 所有主要内容可折叠。
- 全局配色统一，符合医疗 AI 平台的清透高级感。
- `npm run build` 通过。

## 8. 非目标

本次不做：

- 完整 Canvas 圈选坐标输出。
- 真实 SSE 问诊流。
- 真实 ECharts 思维树渲染。
- 后端新增接口。
- 路由大拆分。
- 生产级权限矩阵。

这些能力将在角色化 MVP 稳定后按模块逐步接入。

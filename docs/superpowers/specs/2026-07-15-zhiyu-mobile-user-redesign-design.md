# 知语寻真 Flutter 用户端重构设计

日期：2026-07-15

范围：`mobile/` Flutter 用户端

状态：设计已确认，待实施计划

## 1. 目标与边界

本次重构只覆盖 Flutter 用户端，不设计或修改 Web 管理端。产品是同一个 App，学生和教师使用统一登录入口，登录后根据身份展示不同页面与任务，不拆成两个独立客户端。

重构目标：

1. 去除卡片堆叠、巨大标题、装饰渐变和模板化数据面板带来的 AI 设计感。
2. 建立简约、可信、舒适的临床教学界面，让用户快速看清当前任务和下一步操作。
3. 保留现有 Logo，不重绘、不改色、不改比例。
4. 全部用户可见文字使用自然、准确的中文。
5. 手机竖屏优先，同时保证平板自然伸展和正常使用。
6. 保留现有路由、身份守卫、Repository 和数据模型，避免将视觉重构扩大为业务重写。

不在本次范围内：

- `front/` Vue 用户端和管理端。
- `front/src/admin/`、`front/admin/` 及管理类功能。
- 后端接口、AI 服务和业务规则重构。
- 与病例内容无关的营销页面、氛围图片和装饰插画。

## 2. 设计原则

### 2.1 临床极简

界面应安静、精确、适合长时间阅读。使用冷白背景、深青强调、清楚的中文层级和充足留白。视觉重点来自内容和任务顺序，不来自阴影、渐变或装饰。

### 2.2 任务优先

每个页面第一屏必须回答三个问题：用户在哪里、当前最重要的任务是什么、下一步可以做什么。学生页面围绕训练进程组织，教师页面围绕教学待办组织。

### 2.3 同一产品，两种身份

学生与教师共享 Logo、主题、组件、页面间距、导航形态和交互反馈。身份只改变功能入口、内容和任务优先级，不使用两套颜色，也不在每个页面反复强调“学生端”或“教师端”。

### 2.4 克制的苹果式秩序

参考苹果产品对留白、圆角层级、触控反馈和动效节奏的处理，但不仿制 iOS 系统界面。圆角用于改善触感和建立层级，不把所有文字都放进胶囊容器。

### 2.5 不过度设计

设计中禁止以下模式：

- 大面积深色或渐变主视觉。
- 每组内容都套卡片、边框和阴影。
- 巨大粗体标题和英文大写栏目名。
- 与任务无关的雷达图、圆环图、医生头像和装饰图形。
- 多种强调色同时争夺注意力。
- 为了展示动效而增加的循环动画。

## 3. 产品结构

### 3.1 登录与身份分流

App 只有一个登录入口。登录页展示现有 Logo、产品名称、账号与密码表单。登录成功后读取身份：

- 学生进入学生工作区。
- 教师进入教师工作区。
- 管理身份继续提示使用 Web 管理端，不在移动端提供管理功能。

登录页不使用左右分栏或营销文案。品牌区、表单区和辅助信息通过留白自然分隔。表单支持回车提交、字段内错误、加载状态和中文失败提示。

### 3.2 学生身份导航

底部保留五个高频入口：

1. 首页：今日任务、继续训练、最近反馈。
2. 病例：病例搜索、筛选、详情和进入问诊。
3. 反馈：能力评估和下一步训练建议。
4. 复盘：错题筛选、错误依据和再次训练。
5. 我的：身份信息、三个月训练热力图、学习记录和退出登录。

病例详情和问诊室使用全屏页面。进入全屏流程后隐藏底部导航，并提供清楚的返回方式，避免训练过程被无关入口打断。

### 3.3 教师身份导航

底部保留五个高频入口：

1. 概览：今日待办、作业进度和班级薄弱点。
2. 病例：病例配置，以及进入病例广场的次级入口。
3. 作业：作业列表、截止时间和提交进度。
4. 批阅：待复核队列、问题证据和处理操作。
5. 我的：教师身份、所属信息、教学概况和退出登录。

教师端不采用桌面管理后台的表格或左右双栏。手机上优先使用列表进入详情；批阅详情使用可拖动的底部详情层，病例配置等完整表单使用独立页面。

## 4. 视觉系统

### 4.1 色彩

基础色：

- 页面背景：`#F7F9F9`，接近白色的冷灰。
- 主要表面：`#FFFFFF`。
- 主文字：`#161A1C`。
- 次要文字：`#596367`，必须满足可读对比度。
- 细分隔线：`#E3E8EA`。
- 品牌深青：`#064B59`。
- 品牌按压态：`#003441`。
- 品牌浅底：`#EAF1F2`。
- 成功、警告、错误色只用于真实业务状态，不参与装饰。

页面不使用多色渐变。深青色只用于主操作、当前导航、关键数据和少量标题，不铺成大面积背景。

### 4.2 字体与排版

优先使用设备上质量稳定的中文系统字体。页面标题约 `24-28px`，区块标题约 `18-20px`，正文约 `15-16px`，辅助文字约 `12-13px`。中文标题不使用负字距，不用超粗字重覆盖整个页面。

排版规则：

- 页面标题最多两行，第一屏避免海报式大标题。
- 病例摘要和解释文字保持舒展行高。
- 数据使用等宽数字特性，避免数字变化导致布局跳动。
- 所有用户可见栏目、按钮、提示、空状态和错误信息使用中文。

### 4.3 圆角、边框与阴影

采用分层圆角：

- 普通列表项和内容卡片约 `8px`。
- 输入框和按钮约 `10-12px`。
- 底部弹层、对话框等独立浮层约 `16-20px`。
- 状态标签按语义使用小圆角；只有极短状态适合胶囊形。

普通内容默认不加阴影。底部导航、弹层和固定操作区可使用极轻阴影。内容分组优先依靠留白、标题和细分隔线，只在病例、待办、批阅对象等独立可操作单元上使用卡片。

### 4.4 图标与 Logo

保留 `mobile/assets/images/brand-logo.png`，不修改图形。Logo 在登录页和“我的”页面获得清楚留白，不套装饰性渐变背景。

导航和操作图标使用 Flutter Material 图标集，统一线性风格和尺寸。熟悉操作优先使用图标并提供语义标签；不熟悉操作使用图标加简短中文。医学影像只在病例确实需要时出现。

## 5. 页面设计

### 5.1 登录页

页面从上到下依次为 Logo、产品名称、简短身份说明、账号表单和登录按钮。学生与教师演示身份可作为轻量分段选择，但不渲染成两张大卡片。输入框必须有可见标签，错误显示在字段下方。

### 5.2 学生首页

顶部使用简短问候和当日状态。第一视觉焦点是一个“继续训练”主任务，展示病例名称、当前步骤和明确行动。下方使用无边框列表展示最近病例、待复盘和最近反馈，不堆叠多个统计卡。

首页不展示训练日历热力图。

### 5.3 病例列表

页面以搜索和轻量筛选开场。病例采用纵向列表，每项展示标题、科室、难度、预计时间和训练状态。点击整行进入病例详情，避免在行内堆叠多个按钮。

筛选选中态使用深青文字、底部指示或浅色背景，不使用一排夸张胶囊。

### 5.4 病例详情

内容按患者概况、训练目标、病例资料和注意事项排序。底部使用稳定操作区承载“开始问诊”。页面滚动时操作区保持可用，但不能遮挡正文或系统安全区域。

### 5.5 问诊室

问诊室参考 Stitch 中文对话原型的任务逻辑：

- 顶部固定患者姓名、年龄、性别和必要状态。
- 对话空间使用浅色背景，患者消息在左，学生消息在右。
- 智能导师提示作为低干扰的内嵌提示，不打断对话。
- 底部使用分段控制切换“询问病情”“申请检查”“提交判断”。
- 输入框和发送操作固定在安全区域上方，并随键盘自然抬升。
- 发送后消息平滑插入，自动滚动到最近内容；用户正在查看历史消息时不强制抢夺滚动位置。

### 5.6 能力反馈

页面先给出一句明确结论，再展示病史采集、诊断逻辑、沟通技巧和人文关怀等能力维度。图表是辅助信息，不能占据第一屏。下一步训练建议使用可操作列表，明确跳转目标。

### 5.7 错题复盘

顶部提供状态筛选。列表项直接显示错误类型、病例、错误依据和复盘状态。点击进入复盘内容或重新训练。空状态说明当前没有待复盘内容，并提供返回病例入口。

### 5.8 学生“我的”页面

顶部展示现有 Logo、用户名、身份和简短学习概况。训练热力图位于学习概况之后，展示最近三个月。

热力图要求：

- 横向按周排列，纵向为七天，约 `13 × 7` 个小方块。
- 单格约 `7-8px`，间距约 `3-4px`，使用轻微圆角。
- 空白日使用冷灰，训练强度使用四级深青色阶，不使用渐变。
- 底部显示简短月份文字，不重复堆叠星期标签。
- 上方只保留训练天数、连续训练天数、完成次数三个必要统计。
- 轻触方块显示日期、训练次数和当天完成内容；没有记录时不弹出冗余详情。
- 数据不足三个月时仍保持稳定网格，避免布局跳动。
- 模块直接放在页面留白中，不套厚重卡片。

该模块只参考用户提供图片和力扣热力图的小方块密度与时间表达，不照搬绿色配色，也不引入图片上方的圆环图、雷达图和复杂统计面板。

### 5.9 教师概览

顶部直接说明今天需要处理的事项。待复核、作业进度和班级薄弱点按行动优先级排列。数字服务于行动，不使用三张等宽统计卡作为首屏主体。

### 5.10 病例配置与病例广场

病例配置使用清楚的分组表单和底部保存操作，输入时保留字段标签、校验和草稿状态。病例广场作为病例模块的次级页面，通过列表浏览和引用，不与配置表单挤在同一屏。

### 5.11 作业

作业按状态和截止时间组织为纵向列表。提交人数、总人数和进度直接显示在行内。点击进入详情；创建或编辑操作使用明确文字，不在列表中放置多个低频图标。

### 5.12 批阅

首先展示待复核队列。每项显示学生、作业、问题摘要、分数和状态。点击后从底部滑入可拖动的详情层，显示证据与“通过”“退回修改”等处理操作。详情层展开后允许内部滚动，手机上不使用左右双栏。

### 5.13 教师“我的”页面

与学生页面共享身份区结构，替换为所属班级、教学概况和账号操作。不显示学生训练热力图。

## 6. 交互与动效

动效可以增强方向感，但必须短、稳、可中断：

- 主导航切换：淡入和轻微横向切入，约 `180-220ms`。
- 列表进入详情：使用符合平台习惯的推入转场；返回保持相反方向。
- 底部详情层：从底部滑入并支持下滑关闭，内容较长时内部滚动。
- 列表和卡片按压：轻微透明度或缩放反馈，不改变布局尺寸。
- 筛选切换：选中指示平滑移动，列表内容短暂淡入。
- 消息发送：新消息淡入并轻微上移，输入区不抖动。
- 热力图：首次出现只允许一次非常轻的淡入，不逐格编排动画。

所有动效只使用 `transform`、`opacity` 或 Flutter 原生转场能力，避免宽高动画引发布局抖动。通过 `MediaQuery.disableAnimations` 响应系统的减少动态效果设置。滑动返回、页面滚动和底部层手势必须与系统习惯一致，不自定义复杂手势。

## 7. 状态与反馈

### 7.1 加载

页面使用贴合最终内容形状的骨架加载，不使用页面中央无限转圈。按钮提交时只锁定相关操作，避免整页不可用。

### 7.2 空状态

空状态包含一句原因和一个下一步操作，不使用大插画。例如：“暂无待复核内容，可先查看已完成记录。”

### 7.3 错误

表单错误显示在字段附近。页面数据加载失败时保留页面结构，显示中文原因与“重新加载”。不使用“出错啦”等模糊文案。

### 7.4 成功

成功反馈简短明确，例如“病历已保存”“复核结果已提交”。不会因为成功提示中断当前任务。

## 8. 数据与组件边界

重构继续使用现有 Riverpod、go_router、Repository 和数据模型。页面只通过 Repository 读取业务数据，通过现有身份状态完成路由分流。

公共组件聚焦真实复用：

- 应用主题与色彩、字号、间距、圆角常量。
- 身份共用的底部导航和页面标题。
- 列表行、状态标签、空状态、错误状态、加载骨架。
- 稳定底部操作区和底部详情层。
- 三个月训练热力图。

不建立“万能卡片”或接收大量样式参数的超级组件。学生和教师页面可以共享视觉基础，但业务内容应保留清楚的领域组件边界。

## 9. 可访问性与响应式

- 主要触控目标不小于 `44px`。
- 文本与背景至少满足 WCAG AA 对比度。
- 颜色不能作为唯一状态表达，必须同时提供文字或图标。
- 图标按钮提供语义标签。
- 输入控件支持键盘、焦点顺序和错误朗读。
- 页面宽度适配常见手机竖屏；平板增加左右留白或内容最大宽度，不放大字号形成海报效果。
- 热力图保持小方块尺寸，宽度不足时允许模块内部轻微横向滚动，页面本身不得横向溢出。
- 键盘弹出时问诊输入框和表单操作保持可见。

## 10. 验收与检查

### 10.1 功能流程

- 学生与教师可从同一登录页进入各自工作区。
- 身份守卫阻止跨身份访问页面。
- 学生可完成首页、病例列表、病例详情、问诊、反馈、复盘和个人页面流程。
- 教师可完成概览、病例配置、病例广场、作业、批阅和个人页面流程。
- 问诊输入、筛选、表单保存、批阅操作和退出登录均有明确状态反馈。

### 10.2 视觉检查

- 页面没有大面积渐变、无意义装饰和卡片套卡片。
- Logo 保持原图与比例。
- 圆角层级一致，按钮和输入框触感舒适。
- 所有可见文字为自然中文，无乱码、英文栏目名和占位文案。
- 三个月热力图为紧凑小方块，并位于学生“我的”页面。
- 学生与教师使用同一视觉系统，但任务优先级清楚不同。

### 10.3 设备与质量

- 重点检查约 `360×800`、`390×844`、`430×932` 的手机竖屏。
- 补充检查常见平板宽度，确认内容自然居中且不被过度拉伸。
- 检查系统字体放大、深色系统状态栏、安全区域和软键盘。
- 执行 `flutter analyze`、`flutter test` 和现有测试。
- 对登录、学生首页、病例列表、问诊室、学生“我的”、教师概览和批阅页面进行截图检查。
- 实机或模拟器检查转场、滑动返回、底部层、滚动、输入法和减少动态效果设置。

## 11. 实施约束

实施应按“主题与基础组件、应用壳、学生页面、教师页面、状态补全、视觉验证”的顺序推进。每批改动都保持可运行，并在完成后检查是否重新引入了大圆角卡片堆叠、过重阴影、超大标题或多余动效。

现有工作区包含未提交修改。实施时必须在这些修改基础上继续工作，不覆盖或回退用户已有内容；若发现同一文件存在无法兼容的改动，再单独说明冲突。

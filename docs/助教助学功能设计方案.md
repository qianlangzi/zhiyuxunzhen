## 〇、设计总纲

### 0.1 设计原则（延续项目既有理念）

1. **Rule-first**：能规则确定的不交模型（学情预警触发规则走确定性计算，AI 只做干预建议）。
2. **可复核闭环**：所有 AI 输出保留人工复核与覆盖入口，教师终审权不变。
3. **可追溯**：知识问答必须带教材溯源（书名/章节/页码）；AI 生成内容加"AI 生成"标识（大赛合规声明要求）。
4. **最大化复用**：优先复用现有表/接口/Agent（Assignment、MedicalRecordReview、RagService、SSE 链路），不重复造轮子。
5. **移动端优先**：学生/教师主战场在 Flutter，管理端 Web 保持现状。

### 0.2 与大赛评分对照（为什么要做这些）

| 功能 | 命中评分项 |
| --- | --- |
| AI 知识问答与讲解 | 创意实用度 20 / 内容质量度 20（可追溯、分步引导）/ 交互自然流畅 |
| 智能备课（教学设计+资料+发放闭环） | 技术实现度 20（复杂工作流）/ 创意实用度 20 / 作品完成度 10（闭环） |
| 学情预警报告 | 个性化与自适应 / 学情精准诊断（大赛助教场景明确要求） |
| 简答/论述题批改 | 作业与试题批改（大赛助教场景明确要求"辅助评阅主观题"） |

## 一、功能一：AI 知识问答与讲解（助学）

### 1.1 产品形态

**学生端新增「AI 讲解」入口**（首页卡片 + 底部可扩展），进入对话式问答页。与「AI 问诊室」并列但角色不同：

| | AI 问诊室（已有） | AI 讲解（新增） |
| --- | --- | --- |
| AI 角色 | SP 虚拟病人（被问诊） | 导师/学伴（讲解知识） |
| 输入 | 问诊话术 | 学科问题（概念/指标/诊断依据/步骤） |
| 输出 | 病人应答 + 思维树 | 分步讲解 + 溯源引用 + 追问建议 |
| 知识源 | 病例配置 + RAG | 教材 RAG（zhiyu_textbook） |

### 1.2 能力清单

1. **概念辨析**："心衰和 COPD 呼吸困难怎么鉴别？"
2. **指标解读**："BNP 升高到 800 说明什么？还要看什么？"
3. **诊断依据追问**："为什么这个病例优先考虑肺栓塞而不是心梗？"
4. **分步引导**："请分 5 步讲解急性心梗的诊疗流程"，每步带教材出处。
5. **错题联动**（可选增强）：从错题本点"不懂"跳转到 AI 讲解，自动携带知识点上下文。

### 1.3 技术方案

- **新增 Agent**：`TutorAgent`（`ai/app/agents/tutor_agent.py`），system prompt 强调"分步讲解、溯源优先、不直接给诊疗建议"。
- **新增接口**：`POST /v1/ai/ask/stream`（SSE），复用 chat.py 的流式框架：
  - 输入：`{question, sessionId?, subject:"内科", history?}`
  - 流程：RAG 检索（`rag_service.search`，strategy=hybrid）→ TutorAgent 生成 → SSE 事件 `message` + `citation`（溯源卡）
  - 无权威来源时明确提示"未在当前教材库中找到明确依据"（不编造出处）
- **会话持久化**：复用 `chat_session`/`chat_message_log`（sender 加 `TUTOR`），不建新表。
- **前端**：`mobile/lib/features/student/ask/ask_screen.dart` + 入口卡片；复用现有 SSE 客户端封装。

### 1.4 依赖与风险

- 依赖教材 RAG 有数据（本轮同步修复，见修复章节）。
- 风险：教材无对应内容 → 按设计返回"未找到依据" + 建议换问法（诚实降级，符合项目理念）。

## 二、功能二：智能备课（助教核心重构）

### 2.1 产品形态

**教师端新增一级模块「智能备课」**，把三件事收进一个工作流：

```
智能备课（备课包 LessonPlan）
├── ① 教学设计与 AI 生成（新增）
│     选病例/知识点 + 教学目标 → AI 生成：教案大纲 / 课堂活动建议 / 讨论题
├── ② 病例配置（从原「SP 配置台」迁移）
│     ├── 新建 SP 病例（复用现有 sp_config 全部能力：画像/检查/评分要点/AI 草稿/质检/出题）
│     └── 从病例广场引用（复用现有 quote 机制）
├── ③ 课件资料库（新增）
│     上传 PDF / PPT / MP4 / MP3 → 打标签 → （PDF 可入知识库）
└── ④ 发放闭环（复用现有作业分发）
     发布到班级 → 学生端收到「学习任务」（资料+病例+作业）→ 完成 → 学情回传教师看板
```

### 2.4 前端改动

- **mobile 教师端**：新增 `/teacher/bprep`（智能备课工作台，含 4 个步骤页）；「SP 配置台」「病例广场」入口保留为智能备课的快捷方式（内部逻辑复用）。
- **mobile 学生端**：新增「学习任务」入口（可在待办作业 Tab 中加"资料"区），资料预览：PDF（复用 pdf 阅读器）、视频（video_player）、音频（audio 播放）、图片。
- **front Web 管理端**：不动（教师/学生主战场在 App）。

### 2.5 闭环示意

```
教师：备课包（教学设计+病例+资料）→ 发布到班级
                                        ↓
学生：学习任务（先看资料 → 练病例 → 交大病历）
                                        ↓
学情：OSCE 分/错题/薄弱点 → 回传教师学情看板 + 预警
```

## 三、功能三：学情预警报告（助教）

### 3.1 产品形态

教师端「学情看板」下新增「预警中心」：

```
预警中心
├── 班级预警总览（风险学生数 / 风险类型分布 / 趋势）
├── 预警学生列表（学生名 / 风险等级 高-中-低 / 触发规则 / 建议动作）
└── 单个学生预警详情
       ├── 触发规则明细（哪些指标、连续几次、数值）
       ├── AI 干预建议（补哪些知识点、推荐哪些病例/资料）
       └── 一键生成补救路径（复用 learning_path）
```

### 3.2 预警规则（Rule-first，后端确定性计算，每 6 小时/每日扫描）

| 规则 | 触发条件 | 风险等级 |
| --- | --- | --- |
| OSCE 连续低分 | 连续 3 次总分 < 60 或单维 < 50 | 高 |
| 作业逾期 | 累计 ≥ 2 次未交/补交 | 中 |
| 每日一例断档 | 连续 5 天未完成 | 中 |
| 薄弱点恶化 | 掌握度 < 0.6 且持续 14 天未改善 | 高 |
| 问诊行为异常 | 单次问诊 < 3 轮即提交诊断（草率）或 > 30 轮（低效） | 低 |

**数据来源**（全部现有表）：`chat_session.osce_score_json`、`assignment_instance.status`、`daily_case_submission`、`student_weakness`（含 last_updated 趋势）。

### 3.3 AI 增强

- 新增 AI 接口 `POST /insight/alert`：输入学生预警数据 + 薄弱点 + 错题摘要 → LLM 生成**个性化干预建议**（补哪些知识点、练哪个病例、看教材哪章）——复用 `insight/class` 的模式（纯统计入参 + LLM 归纳）。
- 预警报告导出（P2）：可生成班级预警 PDF。

### 3.4 接口清单

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/teacher/alert/overview` | 班级预警总览（按规则统计） |
| `GET /api/v1/teacher/alert/list?classId=&level=` | 预警学生列表（分页） |
| `GET /api/v1/teacher/alert/{studentId}` | 单个学生预警详情（规则明细） |
| `POST /api/v1/teacher/alert/{studentId}/intervene` | 触发生成 AI 干预建议（调 AI /insight/alert，缓存） |
| `POST /api/v1/teacher/alert/scan` | 手动触发全量扫描（或定时任务自动） |

### 3.5 前端改动

- mobile 教师端：`dashboard_screen` 学情看板加「预警中心」入口 → 新增 `alert_screen.dart`（总览+列表+详情）。

## 四、功能四：简答/论述题批改（助教）

### 4.1 产品形态

把批改从"大病历"扩展为**任意文本主观题**：

```
教师端：题目管理新增「主观题」类型（简答/论述，可配评分要点）
        → 发布「主观题作业」（单选/多选/简答/论述混编 = 组卷）
学生端：逐题作答（文本输入）
AI 批改：按题目评分要点逐条核验 → 结构化评分（要点完整性/逻辑/专业性/表达）
        → 给出评分依据 + 改进建议
教师复核：复用现有复核覆盖流程
```

### 4.2 技术方案（最大化复用现有批阅链路）

- **复用表**：`assignment_instance.medical_record_text` 存答案（JSON：题目id→答案）；`medical_record_review` 存批阅结果（`mistakes_json` 存逐题维度评分）；`reviewer_type` 区分 AI/TEACHER 不变。
- **新增字段**：`assignment.require_medical_record` 已有——新增 `assignment.question_ids_json`（主观题组卷）或新建 `essay_question` 复用 `practice_question` 表加 `question_type`。
- **AI 中台新增**：`POST /review/essay` + `EssayReviewerAgent`（`ai/app/agents/essay_reviewer_agent.py`）：
  - 输入：`{question, scoringPoints(教师配置评分要点), studentAnswer, caseContext?}`
  - 输出：`{totalScore, dimensions:[{name, score, maxScore, basis, suggestion}], comment}`
  - 教师配置评分要点 → 复用现有 `sp_case_config.scoring_points_json` 的结构风格。
- **客观题**：已有判题逻辑（刷题判题），本次只需在组卷里混排。

### 4.3 接口清单

| 接口 | 说明 |
| --- | --- |
| `POST /api/v1/teacher/questions` 扩展 | 支持主观题创建（question_type=essay，带 scoring_points） |
| `POST /api/v1/teacher/assignments` 扩展 | 作业可含题目组卷（question_ids_json） |
| `GET /api/v1/student/assignments/{id}` 扩展 | 任务含题目作答区 |
| `POST /api/v1/student/assignments/{id}/submit-answers` | 提交主观题答案（新增，或并入 submit-record） |
| `POST /review/essay`（AI） | 主观题批改 |
| 复用 | `medical_record_review` 存储、教师复核覆盖接口 |

### 4.4 前端改动

- mobile 教师端：`question_list/edit` 支持主观题（评分要点编辑器）。
- mobile 学生端：作答页支持文本输入（复用现有 practice 流程扩展）。

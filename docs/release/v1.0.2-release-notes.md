## 概览

本轮修复围绕「**AI 学伴无法查看历史对话**」「**问诊多模态图片发不出去**」两个实测缺陷展开，
顺带复核并修复了上一轮遗留的三项风险（思维链吃预算、上传无归属校验、备课素材图片永不识别），
共定位 **6 个独立根因**，横跨移动端入口层 / Java 后端解析层 / AI 中台契约与校验层。

VISION 模型（`qwen3-omni-flash`）本身健康，非模型或多模态能力缺失。

## 一、缺陷根因与修复

| # | 现象 | 根因（层级） | 修复 |
|---|------|-------------|------|
| 1 | 学伴会话历史抽屉永远打不开 | `companion_screen.dart::_openHistory` 用 `Scaffold.of(context)`，而该 Scaffold 正是本 State 的 build 产物 → 向上找不到祖先 Scaffold 抛 `FlutterError`（全库唯一一处误用） | 改用 `GlobalKey<ScaffoldState>` + `currentState.openEndDrawer()`；加 `isEndDrawerOpen` 幂等判断 |
| 2A | 只选图不打字点发送毫无反应；带字发图只发文字、图永久卡在待发送区 | `chat_room_screen.dart` 的分发函数 `_onSend()`（有图转 `_sendImage`）**从未被绑定**，是死代码；按钮与 `onSubmitted` 直连 `_sendMessage()`，后者 `text.isEmpty` 即 return | 按钮 `onTap` 与 `onSubmitted` 全部改绑 `_onSend`；未建会话时选图改为明确提示而非静默 return |
| 2B | 图发出去了，但一律返回「读图服务暂不可用」 | `/v1/ai/vision/analyze` 按契约返回**裸 `VisionAnalysisResult`**（无 `{code,data}` 信封）；`AiHttpClient.postDataWithBearer` 旧实现「无 `data` 字段就 return null」→ 把成功的读图结果整包丢弃 | 增加裸对象兜底：`isObject() && !has("code")` 时原样透传；错误信封仍正常降级 |
| 2C | 安全拦截提示永不显示 | AI 返回 `safety_blocked` 下划线命名，移动端读 `safetyBlocked` | `StudentSessionServiceImpl.analyzeImage` 返回前键名归一 |
| 3 | 学伴发图回复被截断甚至空白 | **思考链与正文共享 `max_tokens`**：mt=2048 时思考吃 1296 → 正文 1241 字被截断（`finish_reason=length`）；mt=320 时正文 0 字 | `LlmClient.stream/_create_stream` 与 `ModelGateway.stream` 新增 `disable_thinking`；`companion_workflow` **仅带图轮次**关思考（实测 585 token 输出完整 963 字），纯文本保留思考 |
| 4 | 任意学生可往他人问诊会话灌图片 | `StudentSessionController.uploadImage` 只校验登录态，未校验会话归属 | 入口补 `requireSessionForStudent(sessionId, UserContext.requireUserId())` |
| 5 | 备课上传的图片永远不被 VLM 识别，且误报「VLM 未配置」 | `lesson_material.file_url` 是**相对路径** `/uploads/...`，而 `_describe_material_image` 用 `urlparse` 判 scheme → 恒 return `""`（功能性缺陷，非单纯 SSRF） | 抽出 `app/core/vision_guard.py::validate_image_url`；lesson 侧新增 `_material_image_ref()`：相对路径 → 本地读 `object_storage_root`（与后端 `UPLOAD_DIR=/app/data/objects` 同一份只读挂载）+ base64 内联，含目录穿越拦截 / 扩展名白名单 / 8MB 上限；外链走同一套白名单 |

## 四、发版操作步骤

> 顺序要求：**先 push `main` 让后端 / AI 修复上线，再构建并挂 APK**，否则用户装了新 APK 仍会撞上未更新的后端。

### 4.1 提交并推送（Windows CMD）

```cmd
cd /d E:\zhiyu
git add ai/app/core/vision_guard.py ai/app/api/vision.py ai/app/api/lesson.py ai/app/services/llm_client.py ai/app/adapters/model_gateway.py ai/app/workflows/companion_workflow.py ai/tests/conftest.py ai/tests/e2e/test_agent_gateway_e2e.py ai/tests/unit/test_lesson_material_image.py
git add backend/src/main/java/com/zhiyu/client/AiHttpClient.java backend/src/main/java/com/zhiyu/controller/student/StudentSessionController.java backend/src/main/java/com/zhiyu/service/impl/StudentSessionServiceImpl.java
git add mobile/lib/features/student/chat/chat_room_screen.dart mobile/lib/features/student/companion/companion_screen.dart mobile/pubspec.yaml
git add docs/release/v1.0.2-release-notes.md

git commit -m "fix(multimodal): repair AI companion history drawer, chat image send path, and vision response parsing" -m "Mobile: use GlobalKey<ScaffoldState> for end drawer; bind _onSend to send button and onSubmitted." -m "Backend: pass through bare AI vision payloads; enforce session ownership on image upload; normalize safetyBlocked key." -m "AI: extract vision_guard; support local material images via base64; add disable_thinking for image turns."
git push origin main
```

### 4.2 等待 CI 部署完成

```cmd
gh run list --limit 5
gh run watch
```

关注 `deploy.yml` 全绿；`ai` 镜像冷构建约 27 分钟，增量约 6 秒。

### 4.3 服务器自检

```cmd
ssh root@8.160.161.158 "cd /opt/zhiyu-new && docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.image.yml --profile web ps"
```

### 4.4 构建 APK

```cmd
cd /d E:\zhiyu\mobile\android
gradlew.bat --stop
cd /d E:\zhiyu\mobile
flutter build apk --release --dart-define=API_BASE_URL=http://8.160.161.158
```

产物：`E:\zhiyu\mobile\build\app\outputs\flutter-apk\app-release.apk`

### 4.5 改名 + 校验和 + 发布 Release

```cmd
cd /d E:\zhiyu\mobile\build\app\outputs\flutter-apk
copy app-release.apk zhiyuxunzhen-v1.0.2.apk
certutil -hashfile zhiyuxunzhen-v1.0.2.apk SHA256

cd /d E:\zhiyu
git tag -a v1.0.2 -m "v1.0.2 multimodal link fixes"
git push origin v1.0.2

gh release create v1.0.2 "E:\zhiyu\mobile\build\app\outputs\flutter-apk\zhiyuxunzhen-v1.0.2.apk" --title "v1.0.2 多模态链路修复" --notes-file docs/release/v1.0.2-release-notes.md
```

> `gh` 若未登录：先执行 `gh auth login`。

## 五、已知项 / 待决策

| 项 | 现状 | 影响 |
|----|------|------|
| release 签名 | `android/app/build.gradle.kts` 的 release 仍复用 **debug 签名**（无 keystore） | 可安装、可分发给评委；上架应用市场需正式 keystore。`key.properties` 与 `**/*.jks` 已在 `.gitignore` 中 |

| tag 与部署 | `deploy.yml` 仅监听 `push: branches [main]` | `push tag` 不会触发部署，Release 需单独创建 |

## 二、题型覆盖审计：错题本收入全不全？

各来源是否进错题本（`student_mistakes`）：

| 来源 | 题型 | 是否入错题本 | 备注 |
|------|------|------------|------|
| 刷题（题库/试卷逐题提交） | 单选/多选/判断/填空 | ✅ | 判分正确（多选无序比较、填空归一化），答错入库 + 异步 AI 归因 + 连对 2 次判掌握 + 连错 2 次标「需加强」，闭环完整 |
| 刷题（题库/试卷逐题提交） | 简答/论述（`short_answer`/`essay`） | ❌ **不入** | `isManualType` 返回 true → correct=null → `syncMistakeForPractice` 直接 return。题库有主观题、学生能作答，但**永远进不了错题本** |
| 问诊 SP（AI 中台 evaluator） | diagnosis/history/exam/record/communication | ✅ | 走 `/api/internal/mistakes/sync`，入库后异步归因 |
| 每日一例·旧版开放作答（`/daily-cases/submit`） | practice + caseId | ⚠️ 半残 | 会入库，但质量差（见三-1）；且移动端 UI 已切到新版，旧版入口实际闲置 |
| 每日病历·新版九段书写（`/daily-cases/mr/submit`） | — | ❌ **不入** | 只落 `daily_case_record/segment/defect`，**完全不写 `student_mistakes`**。移动端「每日病历」页走的就是这条链 |

结论：**客观题闭环是通的；主观题和每日病历两大来源缺口是真实的**。AI 中台的「主观题失分维度归因」（stage=completeness/logic/professionalism/expression）目前是死代码——全系统没有任何地方写入 `mistakeType='essay'` 的错题。

## 三、其他逻辑问题（未修，待方案确认）

1. **每日一例（旧版）错题质量差** `DailyCaseServiceImpl.addToMistakes`：
   - 不设 `wrongCount/consecutiveCorrect/focusFlag`（移动端错次显示为空）；
   - `knowledgeTag=null` → 点「练同类题」必然报「该错题暂无知识点标签」；
   - 不触发 `MistakeAnalysisTrigger`，不像刷题/问诊错题那样异步预生成归因；
   - 按 caseId 不去重，同一病例多期答错会堆多条记录。

2. **主观题归因参数缺失**：`StudentMistakeServiceImpl.callAiAndCache` 调 AI 时 score/essayMistakes 固定传 `null, null`，主观失分维度归因拿不到得分与批阅明细（修二-主观题缺口时需一并补）。

3. **错题卡不展示「我的答案 vs 标准答案」**：VO 返回了 `studentAnswer/standardAnswer`，但 `MistakeEntry` 不解析、卡片不展示，学生复盘时看不到自己当时错在哪、正确答案是什么。

4. **每日一例错题与刷题错题共用 `mistakeType='practice'`**：错题本筛选器无法区分来源（筛选「刷题」会把每日一例错题混进去）。

## 四、验证过的正常逻辑（无需动）

- 每日一例时区统一 `Asia/Shanghai`（`todayCn()`），0~8 点不会取到前一天；缓存日期兜底防跨天脏缓存。
- 每日病历：未发布/未到期排期拒绝提交（防剧透防抢跑）、打卡连击 LeetCode 式（今天没做不打断）、灌水作答判分封顶 25 分。
- 刷题掌握/降级状态机：答对连击+1 达 2 判掌握、再答错归零降级未复习、累计错≥2 标需加强；手动置「已掌握」同步抬高连击数，口径一致。
- AI 归因缓存：SUCCESS 才落库复用，DEGRADED 不落缓存允许重试；异步归因走事务提交后触发（MistakeAnalysisTrigger），不会查不到刚插入的行。

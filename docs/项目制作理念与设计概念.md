# 知语寻真 · 项目制作理念与设计概念提纲

> 本提纲基于对项目**实际代码**的研读整理（`mobile/`、`ai/`、`backend/`、`front/`），
> 不依赖历史文档，聚焦代码里沉淀出的制作理念与设计概念。

---

## 一、项目本质

- **一句话**：面向医学教育「教—学—管」的 AI 临床训练平台，核心是"把 AI 变成可信赖的教研协作者"。
- 三个端：学生/教师共用**同一个 Flutter App 包**（按角色分流），管理端用 Vue3 Web，业务中台 Spring Boot，AI 中台 FastAPI。

---

## 二、核心制作理念（对 AI 的信任与边界）

> 这一节是整份提纲的灵魂，全部可从代码中读到真凭实据。

### 1. 能规则确定的，绝不交给模型（Rule-first）
- `ai/app/domain/policies/`（`safety_policy`、`output_policy`）+ `workflows/consultation_graph.py`：
  - 输入做**安全策略检查**，命中高危（BLOCK）直接终止；
  - SP 的回复做**输出策略校验**，防止泄露隐藏疾病/医学术语，BLOCK 时替换为安全拒答。
- `backend` 的权限、会话归属、状态判定、审核流转全部走确定性规则（`PermissionInterceptor`、Service 层），不由 LLM 决定。

### 2. 绝不伪造结果（Honest Degradation）
- `RagService` / `rag_service.py`：Embedding 凭证未配置时**抛出 `RetrievalUnavailableError`，绝不伪造零向量结果**。
- `consultation_graph.py` 中 RAG 不可用、思维树失败均"降级但不阻断"，并向客户端发 `degraded` 状态事件，明确告知来源不可用。
- 生产环境配置校验（`ai/app/core/config.py`）：**必须关闭 `enable_llm_fallback` 与 `enable_milvus_fallback`** —— 因为 fallback 会产生"合成分数"，绝不能当作生产 AI 结果（代码注释原文明确声明）。
- 理念总结：**AI 宕机时可以说明性降级，但评分/判读等关键链路宁可返回"不可用/人工复核"，也绝不输出假分数。**

### 3. 唯一自主 Agent，其余是可测试的工作流
- `ai/app/agents/` 只有一个真正自主的 Agent：**`SP Agent`**（扮演虚拟病人，可主动调用工具检索教材）。
- 其余能力（思维树 `mentor_agent`、批阅、评分、报告、学习路径、安全）在重构后都收敛为**可重放、可人工复核的 Workflow 或规则模块**，不散落自由行动的 Agent。
- 问诊本身不是线性脚本，而是 **LangGraph 状态机**：
  `load_context → safety_check → rag_search → sp_reply → output_check → persist → mentor_update`，
  带条件分支：上下文校验失败、安全命中高危即提前 END。

### 4. 深层防御 / 三层校验
- **外围**：`load_context` 校验会话归属与病例匹配（防越权）。
- **内层**：`safety_check`（入口）`output_check`（出口）双向夹击。
- **数据**：凡读取的业务数据都来自 Spring Boot 快照，AI 中台不直接访问业务 MySQL。

### 5. 生产可审计、可降级、可运维
- **全链路追踪**：`RequestContextMiddleware` 为每个请求生成/透传 `trace_id`，写入 `contextvars`，贯穿日志与响应头；AI 中台所有关键路径都 `log_event` 打点（检索命中、rewrite、降级、重试等）。
- **强制安全配置**（`config.py` 的 `validate_prod`）：生产拒绝默认 JWT / 内部 Token / ops Token，拒绝 CORS 通配符，必须显式配置 Vision 白名单。

## 三、技术设计概念

### 1. 单一事实来源 + 分层职责
- Spring Boot 是用户/权限/病例/作业/会话/正式成绩的**唯一业务事实来源**；FastAPI 通过内部接口取快照并回写 AI 结果。
- FastAPI 目标分层：`API 层 → Workflow 层 → Agent 层 → RAG 层 → Model Gateway → 外部适配器`，层间用明确接口通信，不共享任意字典。

### 2. RAG 可信知识库（混合检索）
- 三种策略：`dense`（纯向量，最快）→ `hybrid`（BM25 + Dense + RRF 融合，大数据集更优）→ `rerank`（hybrid + LLM 重排，高精度但 +3~5s）。
- **多模态 Embedding**：优先 DashScope `Qwen3-VL-Embedding`（融合文本+图片），降级 OpenAI 兼容文本向量；带 3 次重试 + 指数退避。
- **查询工程**：口语→医学术语改写 + 多轮指代消解（`query_rewriting`）；**自适应迭代检索**——向量 top1 偏低时，对"另一形态的 query"重查一轮并融合。
- **BM25 三层缓存**：内存(RR TTL 300s) → 磁盘 pickle → Milvus 全量重建；增量更新；超 `bm25_max_docs`(20 万) 自动降级 dense 并告警。
- 检索与生成分离：检索只返回带版本/章节/页码的证据（Citation），不负责生成。

### 3. RBAC 权限（后端）
- `PermissionInterceptor` 按路径前缀 + 角色强校验：
  - `/admin/**` → 角色 4(管理员)/5(运维)；`/teacher/**` → 角色 1(教师)，且写操作需 `auditStatus=2`（资质审核通过）；`/student/**` → 角色 0(学生)。
- 数据级权限（教师只能看授权班级、学生只能看本人）由 Service 层校验。

### 4. 移动端架构与「一套代码，两种角色」
- **同一个 Flutter 包**：`appRouter`（go_router）用 `redirect` 统一做登录态 + 角色越权双重守卫——未登录跳登录页；学生误入 `/teacher/*` 或教师进 `/student/*` 都会被弹回对应首页。
- **导航结构**：学生端/教师端各一套 `StatefulShellRoute.indexedStack`（底部 4 Tab 常驻），详情页走顶层路由覆盖 Shell。
- **状态管理**：Riverpod（ProviderContainer + `uncontrolledProviderScope`），`main()` 异步预热 auth/settings，消除 redirect 竞态与主题闪烁。
- **环境注入**：`ApiConfig` 通过 `--dart-define` 编译期注入 API 地址 / AI 地址 / Mock 开关，真机、模拟器、不同环境切换不改代码。

### 5. 数据与离线优先
- 设置、用户态、角色标记全部 `SharedPreferences / FlutterSecureStorage` 本地持久化，"离线优先"。
- 支持生物识别登录（开启前需本人在场验证）、离线缓存开关、WIFI 自动下载等个性化设置项。

### 6. 可靠性兜底
- `main.dart` 全局 `ErrorWidget.builder` 兜底页：build 异常不再白屏/红屏，release 给友好提示、debug 暴露详情定位真机问题。
- `ZhiyuApp` 监听 `AppLifecycleState`，后台/前台切换预留资源管理与重连点。
- HTTP 复用连接池、Redis 连接池、Milvus 线程池均有上限配置，防止资源泄。

## 四、界面设计概念（视觉语言）

> 来自 `mobile/lib/core/theme/app_colors.dart` + `app_theme.dart`，是实际的代码级设计规范。

### 1. 品牌色彩系统（医学感、冷静可信）
- **主色 seed = `moss` 墨绿**（暗喻诊断绿/生命体征），辅助 `amber` 琥珀、错误 `vermilion` 朱红。
- **纸墨语汇**：背景 `paper` 米白、文字 `ink` 墨色、辅助 `card`/`rule` 分隔线——整套是"纸墨/病历"式的低饱和、高对比、接近真实医疗纸张。
- 4 级圆角（`sm/md/full`）：输入/卡片用轻圆角，主按钮全圆，克制典雅。

### 2. 克制的动效
- 全局自定义转场 `_SoftPageTransitionsBuilder`：**「淡入 + 轻上移」240ms、easeOutCubic**，取代系统生硬切换；统一各平台，追求自然层级递进而非装饰。
- Material 3 设计语言，`useMaterial3: true`。

### 3. 明暗双主题（护眼）
- `darkTheme` 基于设计系统深色化：米白/墨绿反转为深墨绿黑背景，主色提亮为 `moss3` 保证对比度；`themeMode` 由设置开关切换。

### 4. 一致性原则（从代码自然长出的）
- 学生端/教师端**共享同一 Theme/Styles/Widgets**，只在导航与职责上分流 —— 印证"一套语言，两种角色"的设计统一性。

## 六、一句话总结

> **这是一个把"对 AI 的克制"写成代码的项目**：能确定的事用规则、关键结果绝不伪造、只有 SP 能自主行动、其余全部可复核；再用一套冷静可信的医学术视觉与离线优先的移动体验，把 AI 训练平台做得可靠、可信、好用。
